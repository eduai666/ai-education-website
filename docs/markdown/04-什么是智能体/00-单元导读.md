# 什么是智能体：单元导读

**智能体不是一个突然变聪明的新“大脑”，而是一套围绕目标工作的 AI 系统。**

它会查看当前情况，判断下一步，使用规则允许的工具，再根据结果继续。任务做完就结束；无法可靠继续，或下一步会产生真实后果时，就先停下来说明情况，等待人来决定。

这个单元不用写代码。我们会一路跟着“去海州市科学馆”这个任务，看清各部分怎样分工、系统怎样行动、什么时候适合使用，以及什么时候必须停下。

前面的单元已经介绍过模型、上下文、工具和 Agent。知道这些部件的名字，只是第一步。

这个单元继续看它们怎样配合：工具请求到底由谁执行？任务状态怎样保留？计划为什么只改一部分？什么情况下，固定程序反而更可靠？

先把立场说清楚：人始终在任务中心。智能体可以补充知识、连接工具、减少重复劳动，但目标和重要决定仍由人掌握。系统越能连续行动，越要让人看得见、改得了、喊得停。

## 这个单元回答六个问题

1. **[从回答问题到完成任务](./01-从回答问题到完成任务.md)：** 智能体和只回答一次的聊天助手，关键区别是什么？
2. **[智能体由什么组成](./02-智能体由什么组成.md)：** 目标与限制、工作环境、任务状态、模型、工具和控制程序分别负责什么？
3. **[智能体怎样一步步行动](./03-智能体怎样一步步行动.md)：** 它怎样观察结果、判断下一步，并检查任务是否完成？
4. **[跟着智能体完成一次任务](./04-跟着智能体完成一次任务.md)：** 新查到的信息怎样改变原来的计划？
5. **[智能体和固定工作流有什么不同](./05-智能体和固定工作流有什么不同.md)：** 自动运行或使用工具，就一定是智能体吗？
6. **[什么时候应该让智能体停下来](./06-什么时候应该让智能体停下来.md)：** 哪些操作可以继续，哪些操作必须先让人确认？

## 为什么按这个顺序学

如果一开始就背模型、工具、上下文和循环，很容易记住词，却看不清任务怎样往前走。因此，这个单元从一件真实任务开始，再逐层拆开：

1. 先比较“回答一次”和“完成多步任务”；
2. 再分清模型、工具、任务状态和控制程序的责任；
3. 接着跟着新结果走过一轮又一轮；
4. 然后用完整案例观察计划怎样局部改变；
5. 最后比较智能体与固定工作流，并划出停止和人工确认的边界。

这条学习路线综合了文末几套入门资料的共同思路。这里不展开代码和框架操作，只保留理解智能体真正需要的部分。

## 学完这个单元，你将能够

- 用自己的话解释什么是智能体；
- 说清目标与限制、工作环境、任务状态、模型、工具和控制程序各自的作用；
- 分清任务状态与模型这一轮实际读到的上下文；
- 用“观察—判断—行动—检查”解释一个多步任务；
- 区分单次聊天回答、固定工作流和智能体；
- 判断哪些操作可以自动完成，哪些操作应该先让人确认；
- 面对来源冲突、工具报错或权限不足时，知道系统为什么应该停下来。

## 学习时抓住一条主线

智能体的能力来自几个部分的配合，不是某一个部件单独带来的。

你可以一直追问：

1. 目标是什么，哪些边界不能越过？
2. 系统现在知道什么，下一步由谁提出、谁执行？
3. 它拥有哪些工具和权限，什么情况下必须停下？

如果这些问题答不上来，“自主完成任务”就说得太含糊了。

## 关于贯穿案例

本单元中的海州市、场馆和查询结果都是教学模拟，不对应真实地点，也不是实际出行建议。真实出行仍要查看场馆当天公告和当地交通信息。
