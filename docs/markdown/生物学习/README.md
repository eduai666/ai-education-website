### 当前实施快照

当前页面已经具备完整 2D 图、三张事实卡、稳定 Structure/Fact ID、可订正到 3/3 的观察挑战、离线 AI 建议判断活动，以及用户主动启动的 Three.js 场景。观察挑战只在当前页面内保存选择，不收集身份信息，也不上传答案。3D 直接使用 Cell Architecture Studio 固定提交中的 `animal-cell-nih.glb`：模型为 84,906 个三角形的 NIH 动物细胞切面，本地保存并按需加载；运行时重新计算法线、应用教学配色，并用透明语义热点补上原始单网格缺少的细胞核和线粒体选择。场景没有纹理、HDR、外部解码器或持续动画循环，支持旋转、缩放、射线选择、独立光环高亮、复位和上下文丢失降级。

生物模块已经通过数据契约测试、类型检查、代码规范、生产构建和 9 个 Chromium 端到端场景。这里的结果属于带有未提交改动的 **G6 工作区预检**，不能替代 G7a：发布前仍要从指定的干净 Git 提交执行 `npm ci` 和完整验证。真实触屏、低端手机性能、教师内容终审、课堂试用和 OSS/CDN 实际部署仍明确标记为待验证。

## 1. 我们要做什么

参考 [Cell Architecture Studio](https://github.com/cclank/cell-architecture-studio) 的“观察细胞—选择结构—阅读说明”交互方式，在现有网站中制作一个更轻、更适合国内课堂环境的细胞学习展示。

界面不逐像素复刻参考站；3D 固定使用已登记来源和哈希的精细 GLB，其余文字、交互和教学结构按本项目的学习路径组织：

1. 孩子观察一个问题；
2. 把想法写成可测试的需求；
3. 对照批准来源，核验 G0 中保存的 AI 生物事实草稿；
4. 把审核后的事实和需求交给 AI，请它复述并提出方案；
5. 在成人准备的受控模板中完成 2D 和 3D 展示；
6. 用固定用例发现并修复问题；
7. 说明哪些内容来自 AI、哪些决定由人作出。

这里的“可复现”分成两层：

- **教学可复现**：另一位教师使用相同输入、模板和评价标准，能得到同类学生证据。
- **技术可复现**：另一位开发者从指定 Git 提交和锁文件开始，能构建出功能一致的演示。

AI 的实时回答通常不能逐字重现。因此，当前开发演示和自动测试使用版本化的本地合成固定回答；正式课堂版本仍需完成流程审核。真实 AI 会话只要求过程可审计，不要求模型再次生成完全相同的文字。

## 2. 第一版固定范围

`bio-cell-demo-v0.2` 的范围在 G0 开始后冻结。要增加结构、实时 AI 或新交互，必须升版本并重新走相关测试。

### 必须包含

- 一个简化的动物细胞；
- 细胞膜、细胞核、线粒体三个结构；
- 旋转、缩放、选择、高亮和复位；
- 鼠标、触屏和外部结构按钮均可完成选择；
- 2D 海报、结构列表和文字知识卡构成完整基础学习路径；
- 3D 不可用时自动保留 2D 内容；
- 一组版本化的本地合成 AI 对话 fixture，并明确它是实现示例而非真实模型回答；
- 每个事实、素材、带 Suggestion ID 的可执行 AI 建议，以及由 AI 驱动的学习内容或开放配置修改均可追溯；普通代码改动由 Git 追溯。

### 明确不做

- 不做完整细胞器百科和复杂生理模拟；
- 不要求学生从零编写 Three.js 场景；
- 不让 AI 直接执行任意代码或修改生产环境；
- 不把实时 AI、境外 iframe、境外字体或境外模型地址作为核心依赖；
- 不收集姓名、声音、照片、学校、账号等儿童个人信息；
- 不在 2C2G、2C4G 或 4C8G 的普通云服务器上运行本地大模型推理。

当前版本使用本地固定的 GLB，没有纹理、HDR 或外部解码器。模型大小为 1,526,232 bytes，SHA-256 为 `416b95d454e4243a49a530e7e9e4447d33c543e838d072ae5128c38bdad7d7c6`；来源、许可、几何统计和运行时改编均按第 10 节资产协议登记。

## 3. 谁负责什么

| 角色   | 负责                                                             | 不负责                             |
| ------ | ---------------------------------------------------------------- | ---------------------------------- |
| 开发者 | 准备受控模板、结构化配置、3D 能力、2D 降级、验证规则和测试工具   | 替学生作出所有内容决定             |
| 教师   | 批准事实来源、AI 工具、素材许可、课堂任务和发布版本              | 把 AI 回答直接当教材答案           |
| 学生   | 写需求、填写知识卡、调整允许的配置、记录 AI 决策、执行测试和反思 | 从零生成或运行任意可执行代码       |
| AI     | 复述需求、提出候选方案、生成待核验草稿、协助分析测试结果         | 充当事实来源、许可证明或最终决策者 |

学生只修改模板开放的字段，例如结构名称、审核后的说明、观察问题、颜色标签和有限场景参数。可执行框架、网络请求、依赖和发布权限由成人控制。

## 4. 学习成果与证据

整个项目只收集五份固定成果，避免课堂结束后只剩一个“看起来能转的网页”。

| 学习成果                 | 固定证据                   | 通过条件                                                            |
| ------------------------ | -------------------------- | ------------------------------------------------------------------- |
| 把观察变成可测试需求     | 1. 观察与需求卡            | 写明用户、学习目标、3 个结构、必要交互、非目标和至少 5 条验收标准   |
| 判断 AI 给出的生物内容   | 2. 事实核验表与来源        | 3 条事实均有教师批准来源、最终表述和审核状态；AI 不作为来源         |
| 与 AI 协作并保留人工判断 | 3. 原型、AI 会话和迭代日志 | 每项可执行建议都有 Suggestion ID、采用或拒绝决定、理由及对应修改    |
| 用证据发现和修复问题     | 4. 测试与独立复现记录      | 固定用例全部执行，保存 1 个预置练习缺陷或实际失败用例的修改前后证据 |
| 认识 AI 和模型的边界     | 5. AI 使用说明与个人反思   | 学生能指出一项 AI 帮助、一项人工决定、一项事实修正和一个模型局限    |

五份成果使用匿名组号，不记录儿童身份信息。匿名试用摘要归入第 4 份成果，不另算第六份。学生小组维护成果草稿，教师汇编五份成果的版本索引，开发者签署其中的构建、性能和故障测试记录。

## 5. 固定输入：G0 成人准备包

教师和开发者先准备下列输入，版本统一标记为 `G0-bio-cell-demo-v0.2`：

1. 一张用于观察的 2D 细胞草图或最小参考演示；
2. 三项待核验的细胞结构事实及对应的固定 AI 原始草稿，每项有 Fact ID；
3. 教师批准的事实来源表；
4. 批准使用的 AI 工具及数据保留说明；
5. 空白的五份成果模板；
6. `fixture-schema-v1` 和一份只用于验证 UI 读取能力的合成示例；它不是 G3 的项目规划回答；
7. 不含外部网络依赖、供 G4/G5 使用的 2D 页面骨架和最小受控 3D 模板；
8. `test-matrix-core-v1`：固定的核心测试和空白需求测试行；每项包含 Test ID、负责人、严重级别、前置条件、步骤、预期结果和证据类型；
9. 一个与正式发布候选隔离、结果确定的练习缺陷，用来学习“测试—修复—重测”；
10. 代码、环境和素材的初始清单。

G0 的通过条件：

- 不注册学生账号、不输入真实个人信息也能完成任务；
- 关闭实时 AI、WebGL 和境外网络后，2D 观察材料仍完整；
- 三项待核验事实和允许使用的来源已经列出；
- 2D/3D 模板、fixture schema 和核心测试矩阵均有版本且通过第二位成人检查；
- 素材作者、来源和许可证已有记录；
- 成人用合成输入完成一次课前预演，确认说明、模板和测试可操作；预演不冒充正式 G1—G7 成果，也不要求提前完成 G7 构建。

任一条件不满足，项目不得进入学生阶段。

## 6. G0—G7 制作流程

每个阶段都必须保存输入版本、产物版本、负责人、日期和审核结果。阶段门槛不能靠口头确认跳过。

主路径为 `G0 → G1 → G2 → G3 → G4 → G5 → G6 → {G7a, G7b} → 完成`；G7a 与 G7b 可以并行，其他阶段未通过时按各节说明退回。

### G0：准备可控起点

- **输入**：本文、当前项目、教师批准的工具和来源。
- **操作**：制作第 5 节的成人准备包，并由另一位成人检查。
- **产物**：`G0-bio-cell-demo-v0.2`。
- **通过**：第 5 节全部条件打勾。
- **未通过**：不开放给学生，继续补齐 G0。

### G1：观察并定义需求

- **输入**：G0 观察材料和空白需求卡。
- **操作**：学生独立观察，再由小组合并需求；此时不让 AI 替学生提出目标。
- **产物**：观察与需求卡 `requirements-v1`。
- **通过**：明确目标用户、一个学习目标、三个结构、必要交互、非目标和至少 5 条可执行验收标准。
- **未通过**：继续澄清 G1，不进入内容或制作。

“AI 理解了任务”不是通过条件。可检查的条件是：AI 后续复述逐项覆盖 `requirements-v1`，所有差异都由学生确认。

### G2：先核验生物事实

- **输入**：G0 中保存的三项 AI 原始草稿和教师批准的来源表。
- **操作**：学生比较固定草稿与来源，教师审核最终表述；此阶段不让 AI 继续生成新事实。
- **产物**：事实核验表 `facts-v1` 和三张知识卡。
- **通过**：每张卡都有名称、简短功能、观察问题、来源和审核人；没有未解决冲突。
- **未通过**：退回 G2；未经审核的文字不得进入原型。

### G3：让 AI 复述、规划，由人决定

- **输入**：`requirements-v1`、`facts-v1`、技术和安全约束。
- **操作**：学生撰写完整、独立的提示词，由教师使用成人管理且已批准的 AI 工具发起新会话；这次课堂调用不集成到产品运行时。AI 复述需求并给出最小计划后，学生逐项采用、修改或拒绝，并把每条验收标准映射到 Test ID。若服务不可用，则使用 G0 合成示例做离线批判练习，记录 `source=offline-fallback`，不得声称它是对本次提示词的实时回答。
- **产物**：带 Prompt ID 的原始会话、AI 复述对照表、人工决策日志、从审核后回答冻结的 `plan-fixture-v1`，以及在核心矩阵上补齐需求用例的 `test-matrix-v1`。
- **通过**：每条需求均被覆盖且至少对应一个 Test ID；差异、风险和不确定项已有人工决定；提示词不依赖此前用户消息、附件或个人记忆。
- **未通过**：需求问题退回 G1，事实问题退回 G2。

### G4：完成 2D 基础路径

- **输入**：审核后的三张知识卡和受控页面模板。
- **操作**：学生填写内容和固定任务 `OBS-001`，开发者模板负责布局与安全校验。
- **产物**：2D 海报、结构列表、知识卡、三道观察问题及答案记录。
- **通过**：不启动 3D、不调用 AI，也能找到并命名三个结构，完成三张知识卡各自的固定观察问题；答案按 `facts-v1` 评分，订正后 3/3 通过；键盘可以操作结构列表。
- **当前实现**：页面支持三题选择、提交、逐题反馈、错题订正和重新挑战；结果仅保留在页面会话中，正式学生成果仍需另行导出或填写学习单。
- **未通过**：先修复 G4，不能用 3D 掩盖基础内容缺失。

### G5：增加受控 3D 交互

- **输入**：通过 G4 的内容、固定结构 ID、固定镜头、模型文件哈希和材质参数。
- **操作**：在成人准备的 Three.js 模板中映射三个结构，完成旋转、缩放、选择、高亮和复位。
- **产物**：可运行原型和带时间、版本、修改理由的迭代日志。
- **通过**：鼠标、实际触屏和外部结构按钮均可选择；键盘可通过外部按钮选择；选中状态不只依赖颜色；复位有效；3D 失败仍保留 G4。
- **未通过**：退回 G4 或 G5；不增加更多细胞器。

### G6：固定测试、修复并重测

- **输入**：G5 原型、G3 冻结的 `test-matrix-v1` 和隔离的练习缺陷。
- **操作**：学生执行 `EDU-*` 和 `UI-*` 内容及核心交互用例；教师审核 `FACT-*` 和 `OBS-*`；开发者执行 `BUILD-*`、`PERF-*` 和 `FAIL-*` 的构建、性能、网络与故障注入。所有人把结果写回同一矩阵，修复后重复同一 Test ID。
- **产物**：完整测试表、日志，以及一个练习缺陷或实际失败用例的修改前后证据；练习缺陷不得进入发布候选。
- **通过**：所有适用的 P0（阻断）和 P1（发布前必须修复）用例全部通过；不适用项必须记录判定依据和批准人；P2 必须有处理决定；每个失败项都有负责人、修复提交或拒绝理由和重测结果。
- **未通过**：内容问题退回 G2/G4，交互问题退回 G5，环境问题退回 G0。

G7a 和 G7b 都以通过 G6 的同一发布候选为输入，可以并行；只有两者都通过，G7 才完成。

### G7a：独立技术复现

- **负责人**：未参与实现的第二位开发者；不与学生试用者混为同一角色。
- **输入**：G6 发布候选、成果 1—3、成果 4 的测试草稿、指定提交、锁文件和复现说明。
- **操作**：从全新 clone 开始构建，并执行 `test-matrix-v1` 中全部 P0/P1 技术用例。
- **产物**：独立构建与复现报告，作为第 4 份成果的附件。
- **通过**：锁文件、fixture 和资产哈希相符；所有 P0/P1 用例与 G6 基线结果一致。“功能一致”只以这些 Test ID 判断，不以截图肉眼相似判断。
- **未通过**：按报告定位后退回相应阶段；不能仅在原作者电脑上宣布完成。

### G7b：同伴试用、展示与反思

- **负责人**：学生、教师，以及未参与制作的匿名同伴试用者。
- **输入**：G6 发布候选、成果 1—3、成果 4 的测试草稿和固定试用任务 `OBS-001`。
- **操作**：同伴完成 `OBS-001`，学生展示需求、AI 决策和测试证据，再独立完成反思。
- **产物**：匿名试用摘要（归入成果 4）、AI 使用说明和个人反思（成果 5）。
- **通过**：试用结果已记录；学生能依据证据解释一项 AI 建议、一项人工决定、一项事实修正、一个练习缺陷或实际失败用例，以及一个模型局限。
- **未通过**：教学内容退回 G2/G4，交互退回 G5，证据退回 G6；反思不合格则补充 G7b。

## 7. AI 会话如何复现

每次 AI 会话保存为不可覆盖的原始记录，至少包含：

- Prompt ID、任务 ID 和成果版本；
- 项目能够控制或读取到的 system/user/tool 上下文和原始提示词；
- 供应商、模型 ID、调用日期和可见参数；供应商未公开的字段记为 `unknown/not-disclosed`，不得猜测；
- 原始回答全文；
- 从回答中提取的可执行建议及稳定 Suggestion ID；
- 学生或教师对每个 Suggestion ID 的采用、修改、拒绝决定及理由；
- 因该建议改动的文件或配置；
- 用来核验内容的来源；
- 提示词、回答和 fixture 文件的 SHA-256。

三类固定材料不能混用：G0 的 `fact-draft-*` 是 G2 要核验的原始事实草稿；G0 的 `fixture-example-v1` 只验证 UI/schema；G3 审核后才生成与 `requirements-v1`、`facts-v1` 绑定的 `plan-fixture-v1`，供正式课程和 UI 测试使用。

fixture 固定为 UTF-8、LF 换行的 JSON 文件，并声明 `schemaVersion`。文件必须包含 Prompt ID、`requirements`/`facts` 版本、按顺序保存的可见 system/user/assistant/tool 消息、模型元数据，以及页面应解析出的结构化结果。SHA-256 按未经格式化或转换的原始文件字节计算。当前运行时代码检查版本、固定结构 ID、来源引用和内容版本关系；`test:data` 在构建前用 AJV 校验完整 Schema；发布前由 `repro:check` 校验原始文件字节哈希。浏览器运行时不重复计算发布哈希。

项目无法证明第三方服务没有内部系统上下文，但可以保证提示词不依赖此前用户消息、附件或平台个人记忆。提示词应在一个新会话中仍能独立理解，可以使用以下最小格式：

```text
Prompt ID: BIO-G3-001
任务: 复述细胞探索器需求并提出最小计划
目标用户: 10—14 岁学生
已确认事实: <粘贴 facts-v1，不允许改写为新事实>
需求与验收标准: <粘贴 requirements-v1>
约束: 只有三个结构；2D 必须完整；不得请求境外资源；不得收集个人信息
输出: 1.逐项复述 2.实现步骤 3.不确定项 4.测试建议
```

当前页面与 UI 测试读取本地合成 fixture，因此核心练习不调用实时 AI。它的 `reviewStatus` 仍是 `implementation-example`，不能冒充经教师审核的真实会话；真实模型输出以后另行保存用于审计，不因它与 fixture 不同而判定构建失败。所有示例使用合成学生输入，不含真实儿童信息。

## 8. 科学事实如何核验

AI 可以起草，但不能作为来源。这里的“批准来源”指教师预先确认的教材、大学、博物馆或科研机构材料。

事实表固定字段如下：

| 字段       | 含义                                                 |
| ---------- | ---------------------------------------------------- |
| Fact ID    | 稳定编号，例如`CELL-MITO-001`                      |
| 待核验内容 | 原始问题或说法                                       |
| AI 草稿    | AI 的原文，不覆盖                                    |
| 来源       | 标题、机构、教材版本与页码或网页链接                 |
| 访问日期   | 查阅来源的日期                                       |
| 来源快照   | 在许可允许时保存快照及 SHA-256；否则记录不可存档原因 |
| 最终表述   | 学生可读且经审核的文字                               |
| 审核人     | 教师或指定内容审核者                                 |
| 状态       | 待核验、通过、有争议或拒绝                           |

当前 `00-可复现基线/cell-demo-v1.json` 是页面读取的运行时内容投影，不是完整的 `facts-v1` 审计记录；它没有保存 AI 原始草稿、审核人和审核日期。整体状态仍为 `pending-teacher-approval`。开发预览可以呈现已对照来源的文字，但正式课堂发布前必须补齐事实审计表并由生物教师终审。

一个事实只有在状态为“通过”时才能进入知识卡。教材版本与页码，或许可允许时保存的网页快照和哈希，是后续复核当时依据的凭据。来源内容变化、链接失效或最终表述改动后，必须重新审核并生成新版本。

## 11. 国内环境与阿里云约束

### 当前部署事实

当前 `next.config.ts` 是标准 Next.js server 配置，没有设置 `output: "export"`、`output: "standalone"`、`assetPrefix` 或静态图片 loader。共享导航的 logo 使用默认 `next/image`，生成页面会请求 `/_next/image?url=...`。因此，普通 `.next/` 是框架内部构建产物，不能当作静态站目录上传 OSS；按当前配置部署仍需要 `next start` 提供页面和图片优化，或者先完成整站静态导出改造。

浏览器运行时的字体由 Next.js 自托管，但根布局使用 `next/font/google`，构建阶段可能访问 Google 字体源；`npm ci` 和 Playwright Chromium 下载也可能受国内网络影响。`FAIL-010` 只证明被测页面的核心浏览器流程没有境外运行时请求，不能证明国内 CI 构建链路已经离线可用。发布流水线应准备许可明确的本地字体、合规 npm 制品缓存和 Playwright 浏览器缓存，并用全新环境验证。

知识卡本身已经本地打包，但“查看原始资料”会跳转 OpenStax 境外链接；它不是完成核心任务的必要条件。若课堂必须现场核验原文，应在许可允许时准备本地快照或教师批准的国内来源。Three.js r185 要求 WebGL2，旧 Android WebView、关闭硬件加速的电脑或远程桌面可能直接降级为 2D，这属于预期路径。

两条可选部署路线是：

1. **当前最小改动路线**：国内 CDN/WAF → Nginx 或 SLB → ECS 上的 `next start`。在 CI 构建，不在 2C2G 生产机执行 `next build`；CDN 长缓存 `/_next/static/*`，并为带 `url/w/q` 查询参数的 `/_next/image` 使用独立且正确的缓存键。
2. **OSS-only 路线**：先对整个网站验证 `output: "export"`，解决 `next/image`、深层路径刷新和 404，再只上传生成的 `out/`。不能上传普通 `.next/`，也不能只验证这一条细胞路由。

### 推荐部署形态

当前 `next build` 已把目标路由标记为静态预渲染，但仓库整体仍使用 `next start` 运行，并未开启纯静态导出。要采用“只用 OSS/CDN、无 ECS”的方案，必须在干净分支中验证 `output: "export"` 对全部现有路由、MDX 和资源处理的影响，并以实际生成目录完成部署测试；仅看到构建输出中的 `○` 不能证明整个站点可直接上传 OSS。

| 层                         | 建议位置                             | 原因                                 |
| -------------------------- | ------------------------------------ | ------------------------------------ |
| HTML、CSS、基础 JS         | 静态优先；CDN 缓存                   | 减少 ECS 压力，弱网更容易命中缓存    |
| 3D chunk、模型、海报、字体 | 阿里云 OSS + 国内 CDN                | 大文件带宽通常早于 CPU 成为瓶颈      |
| 必要的 Next.js 动态能力    | 确认无法纯静态部署后再选择阿里云 ECS | 只承担轻量页面或 API，不承担 3D 渲染 |
| 3D 渲染                    | 学生浏览器                           | ECS 配置不会提升手机 GPU 性能        |
| AI 教学内容                | 第一版本地 fixture                   | 避免跨境、限流、延迟和课堂不可控     |

国内正式上线前需要逐项确认：

- 使用中国大陆节点和域名时所需的 ICP 备案及当地要求的后续备案；
- HTTPS、访问日志、内容安全、隐私说明和未成年人保护流程；
- 字体、脚本、模型、图片、统计和 AI API 不依赖境外域名；
- 构建所需包可以使用合规镜像加速，但不得改写锁文件中的版本和完整性校验；
- AI 工具的数据保留、内容审核、调用地区和失败降级均由教师或运营者批准；
- 用“阻断全部境外域名”的测试证明核心课程仍可用。

### 阿里云服务器档位

下一轮先制作一个隔离的静态导出验证版本。若整个网站和本地 fixture 能纯静态交付，第一版可以只用 OSS/CDN 或静态托管，不必租 ECS。确有 SSR、鉴权或服务端 API 后，才比较 ECS。以下只是候选档位，不是容量承诺。

| ECS 配置 | 适合                                               | 主要限制                                                         |
| -------- | -------------------------------------------------- | ---------------------------------------------------------------- |
| 无 ECS   | 可纯静态导出的第一版，使用 OSS/CDN 或静态托管      | 不能承载必须在服务端执行的 API                                   |
| 2C2G     | 只有少量动态请求的小规模试用；构建在 CI 或本地完成 | 内存余量小，不宜在生产机同时构建、运行多个 Node 进程或做图片处理 |
| 2C4G     | 经过压测后仍需要的轻量 SSR/API 试点                | 仍需 OSS/CDN 分担 3D 资产；高并发和实时 AI 代理需要实测          |
| 4C8G     | 有较多动态页面、API 或后台任务时                   | 不能解决客户端低端 GPU、跨网延迟或大模型推理问题                 |

无论哪一档，都不应让 ECS 直接反复传输大模型或未缓存的 3D 文件。优先扩展 OSS/CDN 缓存和资源压缩，再根据监控决定是否升配 ECS。

固定公网带宽必须写入容量记录。以 5 Mbit/s 为例，理论上约为 0.625 MB/s，一个 2 MB 冷资源单请求就需要约 3.2 秒，尚未计算并发和协议损耗；CDN 首次回源仍会受此上限影响。默认 `next/image` 还会消耗 ECS CPU 和内存，因此保留它时必须通过 CDN 缓存并压测，2C2G 更适合预生成图片或使用国内图片服务。

如果使用 ECS，`repro-manifest` 还要记录实例族、vCPU 架构、区域、系统镜像、带宽、系统盘、Node worker 数、反向代理配置以及 OSS/CDN 配置。仅写“2C4G”不能复现实验。

即使不注册账号，ECS、CDN 和 WAF 日志仍可能包含学生设备的 IP、User-Agent 和时间戳。上线前要明确日志目的、保留期、访问权限、存储地域和删除流程；中国大陆节点、自定义域名和 CDN 的备案与合规要求应向服务商和专业人员核实。

部署验证拆成三类，不互相替代：

1. **ECS/API 冒烟与容量测试**：只测真实的 HTTP 请求，不声称它执行了 WebGL。20 个虚拟用户、5 分钟升压、10 分钟稳定运行只作为首轮冒烟基线，think time 固定为 2 秒。开始前冻结压测工具及精确版本、脚本 SHA-256、端点与请求比例、请求体哈希、10 秒超时、零重试、连接复用设置，以及压测机的配置、区域和可用带宽；任一设置变化都使用新的 Scenario ID。正式并发应由班级人数和每人请求频率推导后重测。
2. **OSS/CDN 测试**：分别测版本化 URL 的冷缓存和热缓存，记录请求 POP、运营商、缓存键、传输字节和命中状态；重复资源的热缓存命中率目标不低于 95%。
3. **真实浏览器测试**：在记录过型号的电脑和低端手机上执行固定交互，测点击到首个可交互 3D 帧、帧时间和降级行为。

若存在 ECS/API，发布前至少满足：

- 无 OOM、进程重启或资源加载死循环；
- ECS 的 CPU P95 低于 70%，内存峰值低于 80%；
- 动态请求错误率低于 0.1%；
- 原站动态响应时间 P95 低于 1 秒；
- 出网流量和费用告警均有记录。

纯静态版本将 ECS/API 项标为“不适用”并写明依据，仍需执行 CDN 和真实浏览器测试。若正式课堂规模、实例配置或请求脚本变化，必须重新压测；20 个虚拟用户通过不能外推成任意并发人数。

| 渲染策略              | 原生 Three.js 按需渲染；仅在选择、复位、尺寸或 OrbitControls 变化时调用`render()`，无动画循环 |

传输量由版本锁定的浏览器自动化脚本采集，汇总 `PerformanceNavigationTiming.transferSize` 与 `PerformanceResourceTiming.transferSize`。脚本、浏览器和自动化工具的精确版本及脚本 SHA-256 写入报告；跨域 OSS/CDN 必须返回 `Timing-Allow-Origin`，字段异常为 0 时判定采集失败。HAR 只作为请求清单证据，不读取非标准的 `_transferSize` 作为验收口径。2D 冷缓存测试使用全新浏览器上下文；2D 首屏包含文档、海报、字体、CSS、共享与页面 JS。点击启动 3D 后的新增量包含 Three.js 运行时 chunk、模型、纹理、解码器、HDR 和所有其他新请求，不能只统计模型文件。

GPU 内存是估算值，不写成浏览器直接测量值。报告固定汇总几何缓冲字节、纹理解码后的 `宽 × 高 × 每像素字节`、mipmap、render target，以及按视口和 DPR 计算的颜色/深度帧缓冲；同时保存计算表。draw calls 在固定镜头、三个结构均显示的场景中读取 `renderer.info.render.calls` 实测。

性能报告必须记录设备型号、操作系统、浏览器、网络、视口、DPR 和测量方法。冷缓存和热缓存各运行至少 3 次，保存中位数和最差值。真实低端手机验证前只能写“待验证”，不能写“低端手机可流畅运行”。

当前自动化已经覆盖：JavaScript 关闭、WebGL2 创建失败、3D chunk 加载超时、模型 404、`webglcontextlost`、按需加载、确定性复位、键盘等价路径和运行时境外请求检查。模型损坏/CORS、`FAIL-006/007/008` 的完整注入、连续交互帧率、真实触屏与真机性能尚未形成发布证据；当前 GLB 不使用外部解码器，因此 `FAIL-004` 不适用，第一版没有实时 AI 适配器，因此 `FAIL-009` 不适用。不得把 Chromium 模拟视口截图当作真实触屏或低端 GPU 通过记录。

低 FPS 只在实际产生连续帧的固定交互脚本中判断：预热 3 秒，再持续旋转或拖动 10 秒；任一连续 5 秒低于 30 FPS 时，将 DPR 从 `1` 降到 `0.75`，再重复同一脚本；仍不达标则转为 2D，并在本次会话中不自动恢复 3D，避免反复切换。按需渲染的空闲阶段不计算 FPS。

固定失败矩阵至少覆盖：

| Test ID      | 级别 | 开发者注入情况                                                  | 必须出现的结果                                                         |
| ------------ | ---- | --------------------------------------------------------------- | ---------------------------------------------------------------------- |

## 14. 完成定义

只有同时满足下列条件，`bio-cell-demo-v0.2` 才能标记完成：

- 第二位开发者从指定的干净 Git 提交和锁文件开始，按文档成功构建；
- 不调用实时 AI 也能完成课程、页面体验和 UI 测试；
- 三条事实、全部素材、带 Suggestion ID 的可执行 AI 建议，以及相关学习内容和开放配置修改均可追溯；普通代码修改可由 Git 定位；
- 三个结构、旋转、缩放、选择、高亮、复位和完整 2D 降级通过测试；
- 鼠标、键盘、真实触屏、弱网和境外阻断用例通过；
- 性能报告写明环境、方法、三次结果、最差值和是否达标；
- 至少保存一次独立复现报告，以及一个预置练习缺陷或实际失败用例的修复证据；
- 学生能解释一项 AI 建议、一项人工决定、一项事实修正、一个练习缺陷或实际失败用例，以及一个模型局限。

页面能打开或 3D 能旋转，都不能单独作为“完成”的证明。

## 15. 版本与变更规则

- 原始提示词、AI 回答、事实来源、资产原件和测试报告只追加，不覆盖；
- 修改事实、提示词、依赖、模型、资源或验收标准时，更新对应清单和哈希；
- 增加细胞器、实时 AI、账号或新学习目标时，升级演示版本并重走受影响的阶段；
- 每次发布都关联唯一 Git commit，不用“最新版本”这类不可定位的描述；
- 修订后保留变更原因、负责人、日期和需要重跑的测试，禁止静默修改。

下一步不是继续堆叠 3D 效果，而是先由生物教师终审三张事实卡，再把本功能和复现材料整理到一个明确的发布提交。第二位开发者随后从全新 clone 执行 `npm ci`、`npm run verify:full` 和 `npm run repro:check`，最后补真实触屏、低端手机与实际部署证据。在这些步骤完成前，当前页面只能称为“可演示的工作区原型”，不能标记为 G7 完成。
