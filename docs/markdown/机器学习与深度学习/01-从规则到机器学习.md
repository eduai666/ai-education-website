# 从规则到机器学习：什么时候应该让计算机“从例子中学”

## 本课目标

完成本课后，你将能够：

- 比较普通程序与机器学习程序的工作方式；
- 解释人工智能、机器学习和深度学习的包含关系；
- 清楚区分训练阶段与推理阶段；
- 判断一个问题是否真的适合使用机器学习。

## 普通程序从明确规则出发

班主任想在运动会后统计团体总分。每个项目的名次已经换算成分数，只要把同一班级的数字相加即可。程序员可以把步骤写得非常明确：

1. 读取每个项目的得分；
2. 检查输入是不是有效数字；
3. 把分数相加；
4. 输出总分。

这类程序的工作方式可以写成：

> **输入数据 + 人写的规则 → 结果**

计算长方形面积、判断整数是奇数还是偶数、到达设定时间后响铃，也都有清楚而稳定的规则。相同输入经过相同规则，应当得到相同结果。规则出错时，人还能顺着程序步骤检查是哪一行、哪一个条件有问题。

因此，“让机器更智能”不等于所有地方都要使用机器学习。如果公式已经确定，普通程序往往更准确、更省资源，也更容易解释。

## 有些规则很难写完

### 猫规则挑战：三条看似合理的规则

现在换一个任务：写规则判断照片里有没有猫。

同学们很快提出三条：

1. 有两只尖耳朵；
2. 有四条腿和一条尾巴；
3. 身上有毛。

老师拿出第一张照片：一只猫躲在纸箱里，只露出圆圆的脑袋，看不见腿和尾巴。第二张是一只无毛猫，不满足“身上有毛”。第三张是狐狸玩偶，尖耳朵、四条腿、尾巴和绒毛全都有，却不是猫。大家继续增加“有胡须”“眼睛形状像这样”“身体不能是布做的”等规则，可新的角度、光线、品种、遮挡和背景又会带来新例外。

难点并不是人完全不知道猫是什么，而是人很难把视觉判断中大量细小、相互配合的线索全部写成固定条件。语音识别也一样：同一句话会因为年龄、口音、语速、噪声而变化。规则不是绝对不能用，而是可能越写越长、越补越乱，仍覆盖不了真实世界。

机器学习把问题换了一种问法：

> 能不能给模型看许多“猫”和“不是猫”的例子，让它根据预测错误调整参数，学到对新照片也有用的模式？

![从训练数据和标签形成模型，再用模型预测新数据的流程](/course-assets/machine-learning/learning-pipeline.svg)

机器学习系统通常包含两个不同阶段：

> **训练数据 + 标签 → 学习算法 → 训练好的模型**
>
> **新数据 + 训练好的模型 → 预测结果**

第一行是**训练**：模型反复看例子、比较答案、修改参数。第二行是**推理**：参数基本固定，模型用已经学到的关系处理新输入。训练可能需要很长时间和很多计算设备；推理一次往往快得多，例如手机在几秒甚至更短时间内给照片分类。

### 垃圾邮件过滤器的三次升级

学校邮箱最初使用一条规则：只要主题里有“中奖”，就移入垃圾箱。很快，发送者把“中奖”写成“中 奖”，规则失效了。管理员增加“免费”“马上点击”“领取奖金”等关键词，又遇到新问题：班级邮件“免费领取运动会号码牌”也被拦截了。

第二次升级加入越来越多的组合条件：关键词出现几次？是否有陌生链接？发件地址是否奇怪？字母是不是全部大写？规则有效了一阵，但发送者不断改变写法，维护清单越来越困难。

第三次升级，管理员收集一批经过确认的历史邮件，每封都标为“垃圾邮件”或“正常邮件”。模型可以同时观察词语、链接数量、发件域名等特征，预测后与标签比较，再调整参数。它不必依靠一个关键词，而能利用多条弱线索的组合。

不过，机器学习并没有让问题自动消失。如果历史邮件大多是中文，新出现的外语诈骗可能识别不好；如果标签标错，模型也会收到错误指导；如果发送者改变策略，模型需要重新评估甚至训练。因此真实系统常把三种力量组合起来：明确危险模式用规则快速拦截，复杂情况由模型评分，重要或有争议的结果交给人复核。

## 机器学习不是“把答案存进去”

假设训练集中有一万张猫图。新照片到来时，模型通常不是在仓库里逐张寻找一模一样的照片。训练算法做的事情更像是调节一张巨大的“数字控制台”：预测错了，就改变许多权重；经过大量例子，参数共同形成从输入到输出的数学关系。

这带来四个重要结论：

- 模型学习的是数据中的**统计模式**，不是永远正确的自然法则；
- 一个参数通常不能简单翻译成一条完整知识，许多参数会共同影响结果；
- 训练表现好，不证明它能处理没见过的照片；
- 更换数据来源、时间或环境后，原有模式可能不再适用。

当然，有些系统确实可能记住个别训练样本，特别是模型很大、数据重复或训练过度时。但“记住一部分”和“整个机器学习就是查表”不是一回事。我们真正关心的是**泛化**：模型能否把从训练样本中得到的有用规律应用到新样本。

### 用一道新题分清训练与推理

训练猫分类器时，模型看到图片 A，预测“狗”，而标签是“猫”。算法计算错误并修改权重，这是训练。几天后，家长拿出从未放进训练集的图片 B，模型输出“猫 87%”，但不再因为这一次使用立刻修改权重，这是推理。

为什么一般不让模型每看一张新图就马上学习？因为新输入可能没有正确标签，也可能是恶意或异常数据。上线后的数据可以经过检查，再用于下一轮训练，而不是毫无防备地改写模型。

## AI、机器学习和深度学习的关系

| 概念 | 关注点 | 例子 |
| --- | --- | --- |
| 人工智能（AI） | 让机器完成通常需要感知、推理、规划或语言能力的任务 | 搜索、规则系统、机器学习、机器人规划 |
| 机器学习（ML） | 让模型从数据或经验中改善任务表现 | 线性回归、决策树、神经网络 |
| 深度学习（DL） | 使用多层神经网络学习复杂表示 | 图像识别、语音识别、大语言模型 |

它们通常可以写成：

> **人工智能 ⊃ 机器学习 ⊃ 深度学习**

可以把人工智能想成一座工具馆。机器学习是其中一个大展厅，深度学习又是机器学习展厅中的一组工具。规则系统也属于人工智能方法，却不一定从数据中训练；决策树属于机器学习，却不是深度神经网络。

这只是范围关系，不是能力排行榜。对于清楚的计费规则，普通程序可能优于复杂模型；对于几百行整齐的表格数据，传统机器学习可能更合适；对于大量图片、声音和文字，多层神经网络常能发挥优势。**合适**比**听起来先进**更重要。

## 什么问题适合机器学习

一个任务更可能适合机器学习，通常是因为：

1. 输入变化很多，很难写出完整规则；
2. 有足够多、来源合理并具有代表性的数据；
3. 正确答案或“做得好不好”能够被定义和测量；
4. 系统允许一定错误率，并有发现、纠正和申诉机制；
5. 数据中的规律在未来一段时间不会立刻完全失效。

一个任务不一定需要机器学习，如果：

- 规则简单明确，例如按确定税率进行一步计算；
- 结果必须精确且可以由公式证明；
- 数据太少、来源不明或标签无法可靠获得；
- 错误可能直接造成严重伤害，却没有人工复核；
- 目标含糊，连人类都无法就“正确答案”达成基本共识。

### 场景判断

| 场景 | 更合适的起点 | 理由 |
| --- | --- | --- |
| 计算长方形面积 | 普通程序 | 公式明确且结果必须精确 |
| 判断照片中是否有交通标志 | 机器学习 | 外观、光线和角度变化多 |
| 温度高于 28℃ 就打开风扇 | 规则与自动化 | 条件清楚，不必训练模型 |
| 根据历史销量估计下周需求 | 机器学习 + 人工判断 | 存在统计规律，也会受天气、活动等突发因素影响 |
| 决定学生是否值得被录取 | 不能只交给模型 | 涉及价值判断、公平、解释和申诉权 |

最后一个场景特别值得停下来想。即使模型能根据历史数据预测“过去哪些人被录取”，也不代表过去的决定都公平，更不代表一个分数能够概括人的潜力。技术上的“可以预测”和社会中的“应该使用”是两个问题。

### 一个实用的五问判断法

面对新项目，依次追问：规则真的写不清吗？数据从哪里来？目标如何衡量？错一次会伤害谁？谁能推翻模型的决定？如果这些问题答不清，就不应因为“AI 很流行”而急着训练模型。

## 常见误区

> [!NOTE]
> **“使用了数据”不等于机器学习。** 电子表格读取数据后按固定公式计算，仍然是普通程序。关键在于模型的参数是否通过数据与反馈发生了改变。

> [!NOTE]
> **“自动给出结果”不等于正在训练。** 已训练好的模型处理一张新图，通常是在推理；只有进入受控制的学习流程并更新参数，才是训练。

> [!WARNING]
> **“准确率高”不自动等于“适合上线”。** 还要看测试数据是否真实、错误集中在哪些情况、错误后果是什么，以及是否有人工复核。

## 检查理解

### 第 1 题

**题目：** 下面哪一项最符合机器学习训练的特点？

- A. 程序员写出所有判断规则
- B. 模型利用样本和反馈调整参数
- C. 计算机随机尝试并永远不检查结果

**正确答案：** B。

**解析：** 机器学习的核心不是“随机”或“自动”，而是根据数据与目标调整模型，使它在任务上的表现改善。

### 第 2 题

**题目：** 手机用已经训练好的模型判断新照片里是否有猫，这属于训练还是推理？

**参考答案：** 推理。模型正在使用基本固定的参数产生预测，没有根据这张照片的正确标签立即更新参数。

### 第 3 题

**题目：** “考试总分计算器也使用学生成绩数据，所以它是机器学习。”这句话哪里错了？

**参考答案：** 总分计算器按人写好的加法规则工作，参数没有通过样本和误差调整。使用数据并不是机器学习的充分条件。

### 思考题

找出生活中的一个智能功能，分别写出它的输入、输出、可能使用的训练数据，以及一次错误会带来什么后果。再设计一种规则与模型协作的方式。

### 家庭与课堂讨论

一人扮演“规则工程师”，尝试用不超过五条规则识别猫；另一人专门寻找反例。然后交换角色。讨论：哪些问题可以靠补规则解决，什么时候例外已经多到应该考虑数据驱动的方法？教师可以特别追问：即使规则难写完，缺少可靠数据时能直接使用机器学习吗？答案仍然是否定的。

## 本课小结

- 规则明确的问题，普通程序通常更合适；
- 现实变化太多、规则难以写全而且有可靠数据时，可以考虑机器学习；
- 训练利用数据和反馈修改参数，推理使用基本固定的参数处理新输入；
- 机器学习寻找统计模式，真正目标是应对没见过的新数据；
- 深度学习是机器学习的一个分支，不是人工智能的全部；
- 能不能建模与应不应该把决定交给模型，必须分别判断。

下一课将打开“训练材料箱”：同一条校园记录里，什么是样本，什么是特征，什么又是标签？有标签、没标签和只有行动奖励时，模型的学习方式为什么不同？
