# 动手实验与章节挑战：观察 Token、概率、注意力与核验

## 活动说明

下面活动的目标不是比较哪个产品“最聪明”，而是把不可见的计算过程转化为可以观察、记录和讨论的现象。

建议为每个活动保存一张记录表：

| 项目 | 记录 |
| --- | --- |
| 我改变的唯一变量 |  |
| 我预测会发生什么 |  |
| 实际观察 |  |
| 与预测不同的地方 |  |
| 可能原因 |  |
| 还需要怎样验证 |  |

每项活动都可以两人一组：一人操作，一人负责记录和提出质疑，中途交换角色。不要只保存“最好看”的结果；失败、意外和与你预测不同的结果，往往最值得分析。

建议给记录表再补四项：

| 项目 | 为什么要记 |
| --- | --- |
| 日期、工具与版本 | 工具更新后结果可能变化 |
| 完整输入 | 少一个空格或条件都可能改变结果 |
| 原始输出或截图 | 避免只凭印象总结 |
| 隐私与版权检查 | 确认没有上传或传播不该使用的材料 |

> [!NOTE]
> “预期现象”不是要求每个人得到相同结果，而是告诉你应该观察哪一种规律。如果观察不同，先检查工具、模型、版本和变量，再把差异写进报告。

## 活动一：比较不同分词方法

- **建议用时：** 15—20 分钟。
- **材料：** 纸笔；可选一个公开分词器演示工具。
- **提交物：** 三类输入的切分截图或手写结果，以及一段 100 字结论。

准备三类文字：

1. 普通中文句子；
2. 中英混合技术词，例如“用 Transformer 处理上下文”；
3. 一段带缩进、括号和变量名的代码。

使用你能访问的模型分词器或 Hugging Face Tokenizers 工具观察切分，记录：

- 中文是按字、词还是混合切分？
- 专有名词是否被拆得更碎？
- 空格和换行是否占 Token？
- 同样意思换一种语言，Token 数是否不同？

结论不能写成“所有模型都这样”，因为不同模型词表不同。

**建议记录：** 为每条输入填写字符数、Token 数、被拆得最碎的部分，并标出空格、标点和换行是否单独占位。

**预期现象：** 常用片段可能成为一个 Token，生僻名字和中英混合词可能被拆得更碎；代码中的括号、换行和大小写可能被保留。不同工具结果可能不同，这正是实验结论的一部分。

**没有工具时的替代方案：** 三名同学分别扮演“逐字分词器”“完整词分词器”和“子词分词器”，把句子写到卡片上并比较词表大小与序列长度。遇到新词“量子猫咖啡馆”时，看谁还能继续切分。

**不要这样总结：** “中文一定比英文更费 Token。”你只观察了有限句子和某个词表，应该写成“在本次工具和样例中，中文句子占用了更多/更少 Token”。

## 活动二：自己当下一 Token 预测器

- **建议用时：** 12—18 分钟。
- **材料：** 20 张小纸片、笔；可选电子表格。
- **提交物：** 四种前文下的候选概率表和一段变化解释。

补全句子：

> 乌云越来越厚，没过多久，天空开始____。

写出至少五个候选并分配总计 100% 的概率。再依次修改前文：

- 风把乌云吹散了；
- 天气预报说今天不会下雨；
- 这是一本奇幻小说的开头。

观察候选分布怎样变化。讨论：

- 最高概率是否一定为真？
- 创作场景与事实场景是否需要相同随机性？
- 如果第一步选了较低概率 Token，后面会怎样调整？

**建议记录：** 每次都让候选概率合计为 100%，圈出最高项；改前文后，用箭头标明哪些候选上升、哪些下降。

**预期现象：** “风把乌云吹散了”会降低“下雨”的主观概率；奇幻小说前提会让原来不常见的候选变得合理。最高概率表示在当前条件下更可能，不表示现实中一定发生。

**小组玩法：** 第一位同学按自己的概率随机抽一个候选，第二位接着写下一步，连续 12 次。最后检查早期一次选择怎样改变整段故事。每一步都通顺，不保证全段事实正确或主题没有漂移。

**替代方案：** 没有随机工具时，把候选按概率写成相应数量的纸片放进袋子。例如 50% 放 10 张、20% 放 4 张，再随机抽取。

## 活动三：用 Transformer Explainer 看模型内部

- **建议用时：** 20—30 分钟。
- **材料：** 可联网浏览器；建议教师提前打开工具并确认可用。
- **提交物：** 一张带标注截图，以及三个“我看到了，但不能过度解释”的结论。

工具：[Transformer Explainer](https://poloclub.github.io/transformer-explainer/)

建议观察：

1. 输入怎样被切成 Token；
2. 每一层的表示怎样变化；
3. 不同注意力头连接哪些位置；
4. 下一个 Token 的候选概率；
5. 调整温度以后分布怎样变化。

> [!NOTE]
> 这是小型演示模型，目的是解释机制。不能用它的行为直接推断所有大型商业模型。

**建议步骤：** 先输入一个短句并截下 Token 切分；再选择某层某个注意力头，记录一个位置与哪些 Token 连接；最后只改变一个词，比较连接和下一 Token 概率。不要一次同时换句子、温度和模型，否则很难知道变化由什么引起。

**预期现象：** 不同层和不同头会出现不同连接，权重并不会固定对应某种人类语法；温度改变候选分布或采样方式，但不会把模型变成事实数据库。

**工具不可用时的替代方案：** 使用本章“借雨伞”的示意权重表。小组为“借”“小周”“下雨”分别画一张权重表，并说明为什么三张表会不同。必须在标题写上“人工设计的解释示意”，不能冒充真实模型数据。

## 活动四：做一次幻觉核验

- **建议用时：** 25—35 分钟。
- **材料：** AI 工具、机构官网或可信数据库、核验记录表。
- **提交物：** 原回答、逐条证据和修订版答案。

请让 AI 回答一个可查证、但不是常识的事实问题，例如某座本地博物馆的开馆年份。不要在问题里提供答案。

按顺序完成：

1. 保存模型原回答；
2. 标出其中每个日期、人名和来源；
3. 打开机构官网或原始文件核对；
4. 判断引用是否真实、是否支持结论；
5. 把错误或不确定内容分成“事实错误、来源错误、过时信息、推测”；
6. 修改提示，要求区分“已知、推测和未知”；
7. 比较第二次回答，但仍要外部核验。

重点不是诱导模型犯错，而是练习证据链。

**建议记录：** 把每条事实拆成独立行，不要整段只写“基本正确”。推荐字段为：`待核验说法`、`AI 给出的来源`、`你找到的原始来源`、`支持/反驳/无法判断`、`处理方式`。

**预期现象：** 模型可能完全正确，也可能在日期、名称或引用上出错。即使这次全部正确，也只能说明这些说法通过了核验，不能推出“这个模型以后不会幻觉”。

**更安全的替代问题：** 若不适合搜索本地机构，可使用教师提前准备的三份公开资料，让 AI 只根据资料回答，再检查它是否遗漏限制条件。不要为了“测试隐私能力”输入真实同学的信息。

## 活动五：比较“模型回答”与“使用工具的回答”

- **建议用时：** 15—20 分钟。
- **材料：** 计算器或电子表格；可选代码环境。
- **提交物：** 三种计算过程、单位检查和误差说明。

选择一道需要精确计算的问题，例如：

> 一个长 17.8 米、宽 9.6 米的长方形场地，铺设每平方米 43.5 元的材料，不计损耗需要多少钱？

分别记录：

- 模型直接心算的答案；
- 使用计算器或代码工具的答案；
- 手工复算；
- 单位与四舍五入规则。

讨论什么时候语言模型应该主动调用工具，而不是只依赖参数中的模式。

**建议记录：** 保存语言模型直接答案、计算器输入串、手算过程和最终单位。若三者不同，先找出差异来自抄数、运算、四舍五入还是单位转换。

**预期现象：** 语言模型有时也能算对，但计算器结果更容易重复验证；语言模型的价值可以是解释题意和选择公式，精确运算则交给专用工具。工具输入错了仍会稳定地产生错误结果，所以“用了计算器”不是检查终点。

**进一步挑战：** 把题目增加“另计 8% 损耗，最后向上取整到整包，每包覆盖 2.5 平方米”。先画计算步骤再输入工具，比较直接把长题交给模型是否更容易漏条件。

## 活动六：拆解一个 Agent 任务

- **建议用时：** 25—40 分钟。
- **材料：** 大纸或流程图工具；不要求真的发送邮件。
- **提交物：** 带权限颜色的流程图和一次故障处理说明。

任务：“找出三条适合中学生的最新 AI 新闻，核对来源，整理成表格并发送给老师。”

先不要执行发送。画出流程并标注：

- 哪些步骤只读；
- 哪些步骤会写文件；
- 哪一步会向外发送数据；
- 哪一步需要人工确认；
- 如何判断新闻是“最新”；
- 原始来源与二手报道如何区分；
- 如果找不到三条可靠新闻，Agent 应如何停止。

**建议记录：** 用绿色标只读步骤、蓝色标可逆写入、红色标对外或不可逆动作；每个工具框旁写清输入、输出和失败信号。

**预期现象：** “核对来源”通常不只是一次搜索，而包括打开原始页面、比较日期和处理冲突；发送应与写草稿分开，并在两者之间加入具体人工确认。

**故障卡：** 随机抽取一种情况加入流程：网页打不开、两条来源互相矛盾、文件写入失败、收件人同名、预算已用完、网页要求上传通讯录。流程必须说明继续、重试、换来源还是停止，不能默认 Agent 总能成功。

**不使用真实账号的替代方案：** 全程只在纸上模拟。由一名同学扮演搜索工具、一名扮演文件工具、一名扮演审批人；工具可以返回失败卡，Agent 设计者必须根据结果调整。

## 活动七：把“大”变成可以感受的数量

- **建议用时：** 20—30 分钟。
- **材料：** 计算器、纸笔；可选电子表格。
- **提交物：** 一张参数数量级说明卡。

选择 70 亿、700 亿和 1750 亿三个示意参数规模，完成下面换算：

1. 假设每秒数一个参数，连续数完分别要多少年？
2. 假设每个参数保存为 2 字节，仅权重大约需要多少 GB？
3. 如果改成 1 字节，存储量怎样变化？这种压缩可能带来什么取舍？

计算时使用：一年约为 365 × 24 × 60 × 60 秒，1 GB 的十进制近似值为 10 亿字节。先写公式，再使用计算器，不要只抄结果。

**预期现象：** 参数数量从 70 亿增加到 700 亿，不只是“多一个零”，数数时间和权重存储也约增加 10 倍。参数规模能帮助理解工程挑战，却不能单独给能力排名；数据、训练方法、架构和激活参数同样重要。

**时间线替代玩法：** 如果课堂不做计算，可以把“统计语言模型、神经语言模型、Transformer、预训练、指令对齐、多模态、Agent”写成卡片，小组按因果关系排列，再为每次变化写一句“解决了什么旧问题”。不要把时间线讲成模型在某一天突然觉醒。

## 章节挑战：制作一张“大模型说明卡”

选择一个你正在使用的 AI 产品，只基于公开可靠资料填写：

### 基础信息

- 输入和输出模态：
- 是否公开底层模型名称：
- 是否公开参数量：
- 是否使用搜索或工具：
- 上下文或文件限制：

### 数据与能力

- 官方说明覆盖哪些任务：
- 哪些能力是模型本身，哪些来自工具：
- 知识更新时间或检索方式：
- 公开评估是否代表你的真实用途：

### 风险与控制

- 数据是否用于训练，能否关闭：
- 是否有儿童或学校使用说明：
- 能执行哪些外部动作：
- 关键动作是否需要确认：
- 怎样导出、删除或申诉：

### 你的判断

- 最适合的三个场景；
- 不适合的三个场景；
- 使用时最重要的核验步骤；
- 还没有公开、因此不能确定的信息。

如果参数没有公开，正确写法是“官方未公开”，而不是引用网络传言。

### 评分量规（Rubric）

每项 0—3 分，总分 15 分。可以先自评，再请同伴指出一条最需要补强的证据。

| 维度 | 3 分：证据充分 | 2 分：基本完成 | 1 分：明显不足 | 0 分：缺失或误导 |
| --- | --- | --- | --- | --- |
| 信息准确 | 关键事实均核验，未知处明确写未知 | 少量次要信息未核验 | 多处只依赖模型回答 | 编造或把传言当事实 |
| 来源质量 | 主要使用官方说明、论文或原始文件 | 原始来源与可靠二手来源混合 | 多为搜索摘要或无作者网页 | 没有来源 |
| 系统拆解 | 清楚区分模型、检索、工具和界面 | 能区分大部分组成 | 把产品能力都归给模型 | 完全没有拆解 |
| 风险与权限 | 结合真实用途提出具体核验和确认 | 列出风险但措施较笼统 | 只有“注意安全”等口号 | 未讨论风险 |
| 表达与反思 | 结构清楚，能说明不确定与个人判断 | 内容完整但反思较少 | 大量复制说明文字 | 无法解释自己的内容 |

**优秀说明卡不等于给产品打高分。** 如果官方没有公开参数或训练数据，准确写出“未知”并解释这会限制哪些判断，同样可以得到高分。

### 提交前同伴检查

交换说明卡，检查者只做三件事：随机打开一个链接；挑一个数字重新计算；挑一句结论询问“来源真的支持这句话吗”。作者根据反馈修订，并保留修改记录。

## 章节测验

### 第 1 题

Token ID 734 比 Token ID 27 更重要吗？

**答案：** 不一定。ID 只是词表中的查表地址，数字大小本身没有语义顺序。

### 第 2 题

自注意力中的 Value 主要表示什么？

**答案：** 某个位置被关注后能够提供的内容表示；Query 与 Key 决定匹配和权重。

### 第 3 题

为什么同一个提示可能得到不同回答？

**答案：** 模型输出概率分布，系统可能采样而非总选最高概率；温度、Top-p、随机种子、模型版本和系统上下文也会影响结果。

### 第 4 题

RAG 能保证没有幻觉吗？

**答案：** 不能。检索可能漏掉或取错资料，模型也可能误读或不忠实使用片段，引用仍需核对。

### 第 5 题

Agent 能发送邮件，是因为大模型本身拥有邮箱权限吗？

**答案：** 不是。系统必须提供邮件工具与明确授权；能力取决于模型判断和系统允许的动作。

## 给家长和教师的话

陪伴学习时，可以要求孩子每次保留三样东西：

1. 原始问题和提示；
2. 使用的来源、工具与修改过程；
3. 自己的判断、核验和最终表达。

这比只看最后答案更能反映真实学习，也能降低把 AI 输出误当成自己独立完成的风险。
