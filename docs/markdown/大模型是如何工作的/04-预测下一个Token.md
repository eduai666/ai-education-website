# 预测下一个 Token：回答怎样一小步一小步生成

## 本课目标

- 解释因果语言建模与自回归生成；
- 理解概率、采样、温度和上下文窗口；
- 说明“预测下一步”为什么能形成复杂能力，也为什么会产生错误。

## 核心任务听起来像文字接龙

给定前文，模型学习：

$$
P(t_i\mid t_1,t_2,\ldots,t_{i-1})
$$

意思是：知道前面所有 Token 时，第 $i$ 个 Token 出现的概率。

例如输入“北京是中国的”，模型会为整个词表计算候选概率。“首都”可能最高，“城市”“中心”等也可能有较低概率。

![大语言模型计算候选概率，选择一个Token接回上下文并继续预测](/course-assets/large-models/next-token.svg)

### 一张会不断分叉的概率树

假设输入是：

> 傍晚，乌云越来越厚，天空开始……

下面的数字只是教学示意。模型第一次可能给出：

| 第一步候选 | 概率 |
| --- | ---: |
| 下 | 46% |
| 打 | 21% |
| 变 | 12% |
| 飘 | 8% |
| 其他全部 Token | 13% |

如果系统选中“下”，上下文就变为“天空开始下”，第二步的概率表可能是：

```text
下 ── 雨 72% ── 了 54% ── 。 63%
  ├─ 降 13% ── 温 41% ── ……
  └─ 沉  4% ── ……
```

如果第一步选中“打”，后面又可能形成另一棵树：

```text
打 ── 雷 58% ── 了 47% ── 。 51%
  ├─ 开 17% ── ……
  └─ 在  6% ── ……
```

模型并没有在开始时把整句“天空开始下雨了”从抽屉里取出来。它先走一步，再把脚下的新位置当成下一步的起点。走过的路会改变后面的路口。

一条完整路径的可能性与沿途每一步都有关。若早期选了“打”，后面即使每一步都很流畅，也不会自动回到“下雨”那条路径。这正是自回归生成既能创造多样答案、又会让早期错误扩散的原因。

> [!NOTE]
> 真实模型会同时给包含成千上万个 Token 的词表打分，而且一个汉字不一定就是一个 Token。上图只是把最重要的几个分支画出来。

## 自回归生成的循环

1. 读取当前上下文；
2. 计算下一个 Token 概率；
3. 按生成规则选择一个 Token；
4. 把它接到上下文末尾；
5. 再次运行模型；
6. 遇到结束标记、长度上限或系统停止条件后结束。

模型每一步只决定很小的单位，但几十、几百或几千步可以组成段落、代码和长文。

## 训练时为什么能并行

训练数据已有完整文字。通过因果遮罩，每个位置只能使用左侧 Token，却可以同时计算许多“前文 → 正确下一 Token”的任务：

| 模型可见的前文 | 目标 Token |
| --- | --- |
| 春 | 天 |
| 春天 | 来 |
| 春天来 | 了 |
| 春天来了 | ， |

生成时没有现成后文，因此必须把自己刚生成的结果接回去，逐步运行。

## 为什么相同问题可能得到不同答案

如果永远选概率最高的 Token，输出更稳定，却可能重复、僵硬或陷入局部模式。系统可以从一组高概率候选中采样。

### 温度

温度调整概率分布：

- 较低：更集中在高概率候选，输出更稳定；
- 较高：候选更分散，创造性增加，也更容易跑偏。

### Top-p

只在累计概率达到某个阈值的最小候选集合中采样，避免从极低概率的巨大词表尾部乱选。

### 随机种子

控制采样随机过程。在模型、提示和系统设置相同时，固定种子有助于复现，但不同平台未必保证完全一致。

## 只预测下一步，为什么能回答问题

要在海量文字中持续预测得好，模型必须压缩许多支撑文字的结构：

- 语法、指代、文体和篇章组织；
- 概念、人物、地点与事件的共现关系；
- 代码语法、函数调用和错误修复模式；
- 问题、步骤和答案之间的关系；
- 不同任务说明与输出格式。

规模扩大、数据多样和训练改进后，这些模式可以组合到新任务中，形成零样本、少样本和上下文学习能力。

但这不等于模型内置了“事实真伪检查器”。训练目标首先奖励合理后文，不保证每个事实都真实。

这部分值得慢一点读。下一 Token 任务看起来简单，但要在各种文本中连续猜对，它必须找到文字背后可重复使用的结构。

### 预测语言：不学语法就很难一直猜对

看到“这些花朵非常……”，后面更可能出现“美丽”，而不是“跑步”。模型若想降低大量句子的预测误差，就要区分名词、动词、修饰关系、单复数、指代和篇章结构。它不一定像学生一样背诵语法规则，却会在参数中形成能支持正确预测的规律。

例如：

> 小美把书递给安安，因为**她**已经读完了。

为了预测“她”之后的文字，模型要利用人物、动作和上下文。句子越长，仅靠相邻词搭配越不够。

### 预测知识文本：要压缩事实之间的联系

教材里常出现“水在标准大气压下达到 100 摄氏度时……”。要把后文预测好，模型会学到“水、温度、沸腾、大气压”等概念经常怎样联系。大量人物、地点、年代和概念关系也会以分布式方式进入参数。

这更像把许多书的规律压缩成一张不完美的知识地图，而不是把网页逐页扫描进数据库。地图能帮助找到方向，也可能丢掉门牌号、混淆小路或停留在旧版本。精确日期、出处和最新消息仍应查原始来源。

### 预测代码：格式看似严格，运行才能验真

训练材料中若包含许多程序，模型为了预测右括号、变量名或下一行，会学习函数定义、循环、常见库和报错修改的模式。例如看到：

```python
total = price * quantity
print(
```

右括号、变量和字符串都受到程序结构约束。这让模型能补全代码，却不保证补出的程序能运行。变量可能未定义，库版本可能不同，逻辑还可能有安全漏洞。代码的优势是可以通过运行、测试和对照输入输出来验证。

### 预测解题过程：能模仿步骤，也可能在中途走错

如果训练数据包含“问题—推导—答案”，模型会学习常见解题步骤的写法。经过专门训练后，它还可能在回答前分解任务、比较几种路线或使用计算器。

但一串很像解题过程的句子不等于严格证明。例如计算长方形面积时，它可能正确写出“长×宽”，却抄错一个数字；后文再围绕错误结果继续解释，读起来仍然连贯。因此，数学题要复算，科学结论要查证，代码要运行。

这四类能力可以用一句话连接起来：

> **为了在语言、知识、代码和解题文本中预测得更准，模型学习了支撑这些文本的许多模式；规模和训练让这些模式能够重新组合，但重新组合不等于永远正确。**

## 上下文窗口不是永久记忆

上下文窗口是一次计算能处理的 Token 范围。它可能包含：

- 系统指令；
- 当前对话；
- 上传文档的片段；
- 搜索或工具返回结果；
- 模型尚未输出的预留空间。

窗口很长也不保证模型同样准确地使用每一处细节。聊天产品的长期“记忆”通常是模型外的存储与检索，不是对话中自动重新训练参数。

可以把上下文窗口想成一张书桌。系统指令、聊天记录、上传材料、搜索结果和即将生成的回答都要占桌面。书桌变大，能同时摊开的纸更多，但桌子再大也不代表模型会仔细读到每一行。旧资料如果被收进柜子，需要搜索或记忆系统重新拿回来；它不会因为曾在一轮对话中出现，就自动永久写进模型参数。

当你说“还记得我三个月前说过的话吗”，产品可能从外部存储中取回摘要。这里应区分三件事：

| 名称 | 保存在哪里 | 是否会自动改变模型参数 |
| --- | --- | --- |
| 当前上下文 | 本轮输入给模型的 Token 中 | 否 |
| 产品记忆 | 模型外的数据库或摘要系统中 | 通常不会 |
| 训练所得知识 | 模型参数中 | 需要训练过程才会改变 |

## 一步错误为什么会扩散

自回归生成把自己的输出变成后续输入。如果早期生成了错误日期、错误变量名或错误前提，后面可能继续在这个错误世界里保持语言上的自洽。

降低风险的方法包括：

- 检索权威来源；
- 调用计算器或代码工具；
- 分步骤检查中间结果；
- 让不同方法交叉验证；
- 在关键结论处要求证据；
- 由人复核高风险输出。

## 小活动：你来预测下一个 Token

补全：“乌云越来越厚，没过多久，天空开始____。”

写出三个候选和概率。然后把前文改成“风把乌云吹散了”，重新分配概率。

思考：

- 概率最低的答案是否绝对不可能？
- 只改变一句前文，为什么概率会改变？
- 连续 100 次选择会不会在中途偏离原主题？

可以再做一次“场景切换”：把前文改成“这是一本魔法小说，乌云其实是一群会唱歌的鲸鱼”。你会发现，低概率候选不是永远错误；新的上下文会重排整张概率表。创作需要保留这种可能性，事实问答却需要更多证据和更谨慎的生成设置。

## 本课小结

- 因果语言模型预测给定前文时的下一 Token 概率；
- 自回归生成把每次输出接回上下文；
- 温度和采样规则影响稳定性与多样性；
- 预测任务迫使模型学习许多语言和知识结构；
- 生成的概率连贯性不等于事实正确，早期错误还会累积。
