# 注意力与 Transformer：一句话里的信息怎样相互联系

## 本课目标

- 直观解释自注意力；
- 理解 Query、Key、Value 和多头注意力；
- 认识 Transformer 一层中的主要结构与局限。

## 为什么顺序处理不够

RNN 会把历史状态一步步传下去，但很长句子中，早期信息可能变弱；顺序计算也限制了大规模并行。

Transformer 提出另一条路线：让序列中不同位置直接计算关联，再按相关程度汇总信息。2017 年的《Attention Is All You Need》最初用于机器翻译，后来成为现代大语言模型的重要基础。

可以把旧路线想成传话游戏：第一位同学听完一句话，把记住的内容传给第二位，再传给第三位。队伍很长时，开头的细节可能在传递中变弱。Transformer 更像让全班同学都拿到同一张句子卡，每个人可以直接查找与自己最相关的位置；训练时，许多位置还能同时进行这种查找。

这并不表示 Transformer “看一眼就理解整篇文章”。它仍要经过一层又一层计算，只是信息不必永远沿着一条单向队伍传递。

## 自注意力在问什么

处理每个 Token 时，自注意力都会计算：

> 当前这个位置，应该从其他哪些位置取多少信息？

例如：

> 小林把雨伞借给小周，因为外面正在下雨。

处理“雨伞”时，“借给”“小周”“下雨”可能提供不同信息。下一层或另一个注意力头会重新计算，关系并非永久固定。

## Query、Key 和 Value

每个 Token 的当前表示通过三组线性变换得到：

- **Query（查询）：**我现在需要寻找什么信息？
- **Key（键）：**我能与哪类查询匹配？
- **Value（值）：**如果被关注，我提供什么内容？

### 先用图书馆理解一次查找

小林去图书馆查“为什么雨伞能挡雨”。他手上的问题是 Query；每本书封面和目录里可供检索的线索是 Key；真正翻开书后读到的解释是 Value。

Query 和 Key 匹配得高，只表示“这本书看起来值得多读一些”；最后汇总进笔记的内容来自 Value。模型里没有真的图书管理员，三者都是由同一个 Token 当前的向量分别乘上三组参数得到的新向量。

再看句子：

> 小林把雨伞借给小周，因为外面正在下雨。

假设某一层、某一个注意力头正在更新“借”这个位置。下面是一张**教学用的示意权重表**：

| 被查看的位置 | 小林 | 雨伞 | 借 | 小周 | 下雨 | 其他位置合计 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| “借”的注意力权重 | 22% | 31% | 8% | 27% | 7% | 5% |

这一轮计算可以按三步读：

1. “借”的 Query 与各位置的 Key 比较，得到一组原始分数；
2. softmax 把分数变成总和为 100% 的非负权重；
3. 系统按这些权重混合各位置的 Value，使“借”的新表示同时带上“谁借、借什么、借给谁”等线索。

31% 并不表示“雨伞贡献了句子 31% 的真正含义”，更不表示模型给出了完整解释。这只是某一层、某一头、某一位置的一次计算。下一层处理“借”时会产生另一张表；另一个头也可能更关注“因为”和“下雨”之间的关系。

简化计算可写成：

$$
\operatorname{Attention}(Q,K,V)=\operatorname{softmax}\left(\frac{QK^T}{\sqrt{d_{k}}}\right)V
$$

不用背公式，只要抓住三步：

1. Query 与所有 Key 计算匹配分数；
2. softmax 把分数变成权重；
3. 按权重对 Value 加权汇总。

除以 $\sqrt{d_{k}}$ 是为了让数值尺度更稳定，其中 $d_{k}$ 表示 Key 向量的维度。

> [!NOTE]
> 如果公式让你觉得突然，可以先只记住“匹配—变成权重—加权汇总”。公式是在精确描述同一件事，不是理解后文的门槛。

## 为什么要多头注意力

一句话中可能同时存在：

- 谁执行动作；
- 动作作用于谁；
- 代词指向哪个名词；
- 前后是否转折；
- 代码变量在哪里定义和使用；
- 某个格式是否在远处闭合。

多头注意力让模型在不同表示子空间中并行寻找关系。不能保证某个头永远负责“语法”或“指代”，但多个头联合通常比单一视角更有表达力。

## 一层 Transformer 还包含什么

注意力不是 Transformer 的全部。典型一层还包括：

- **前馈网络（MLP）：**对每个位置的表示进一步非线性变换；
- **残差连接：**让原信息与新变换相加，帮助深层训练；
- **归一化：**稳定不同层之间的数值；
- **因果遮罩：**生成模型训练时禁止当前位置偷看未来 Token。

多层堆叠以后，每个 Token 表示会反复汇总上下文、变换和重组。

### 一层像一次小组讨论加个人整理

仍用课堂来想象，但要记得这只是帮助入门的比喻：

- 注意力阶段像小组讨论，每个位置从其他位置取回与当前问题相关的信息；
- 前馈网络像每位同学回到座位后独立整理笔记，把刚获得的信息重新组合；
- 残差连接像保留旧稿，再把新发现写在旁边，避免每轮讨论都把原信息全部擦掉；
- 归一化像调整不同人说话的“音量”，让数值不要在很多层后失控；
- 因果遮罩像考试挡板：预测第 5 个 Token 时只能看第 1 到第 4 个，不能偷看答案。

经过几十层甚至更多层，这个过程不断重复。较早层可能形成局部词语和句法线索，较后层能够组合更长范围的信息，但不能把每一层简单标成固定的人类学科。

### 用“它”检验远距离联系

比较下面两句：

> 小猫没有钻进纸箱，因为**它**太小了。
>
> 小猫没有钻进纸箱，因为**它**太大了。

两句话只换了最后一个字，“它”更可能指向的对象就会变化：第一句可能是纸箱太小，第二句可能是小猫太大。模型需要把代词、否定、动作、物体尺寸和常识线索组合起来，而不是只找离“它”最近的名词。

你可以试着圈出自己判断时参考了哪些词，再想一想：如果删掉“没有”，答案会不会变化？这正是注意力要帮助网络解决的问题类型之一。

## 编码器、解码器和仅解码器模型

原始 Transformer 同时有编码器和解码器：编码器理解输入，解码器生成输出。后来形成不同路线：

- **仅编码器：**擅长理解、分类与生成表示；
- **编码器—解码器：**适合翻译、摘要等输入到输出任务；
- **仅解码器：**根据已有上下文自回归生成，是许多聊天式 LLM 的基础。

## 标准注意力的代价

如果序列有 $N$ 个 Token，标准全注意力需要考虑许多两两关系，计算与内存通常随 $N^2$ 增长。上下文翻倍，相关开销可能增长约四倍。

因此长上下文系统会使用：

- KV 缓存减少重复计算；
- 局部、稀疏或分块注意力；
- 更高效的注意力实现；
- 检索系统只取回相关资料；
- 对历史信息进行压缩或总结。

KV 缓存可以减少生成时对旧 Token 的重复计算，但不会让上下文变成无限，也不会消除注意力在长序列上的所有成本。检索则采取另一种思路：不把整座图书馆全部摆到桌面上，而是先选出可能相关的几页，再交给模型阅读。检索选错页时，模型照样可能得出错误答案。

## 注意力权重不等于完整解释

权重图可以展示某一层、某个头的关联，但最终输出还经过许多层、残差路径和前馈网络。高权重不一定代表因果依据，也不能证明模型拥有人的“注意体验”。

> [!NOTE]
> “注意力”是数学机制的名字，不是意识证据。

## 检查理解

**题目：** 为什么 Transformer 比传统 RNN 更适合大规模并行训练？

**参考答案：** 训练时它可以同时计算序列中许多位置的表示，而不必严格等前一步完成再处理下一步；自注意力还能直接建立远距离位置的联系。

**再想一步：** 在上面的“借雨伞”例子中，如果“雨伞”的注意力权重最高，能否宣布模型最终回答一定由“雨伞”决定？

**参考答案：** 不能。那只是某一层、某一个头、某个位置的一次权重；最终输出还会经过其他注意力头、前馈网络、残差路径和很多层计算。

## 本课小结

- 自注意力按相关程度汇总其他位置的信息；
- Query 用于寻找，Key 用于匹配，Value 提供内容；
- 多头注意力提供多个关系视角；
- Transformer 还依赖前馈网络、残差连接、归一化和遮罩；
- 标准注意力对长序列成本高，权重图也不是完整解释。
