# 从基础模型到 AI 助手：会续写，不等于会帮助人

## 本课目标

- 区分预训练、指令微调和偏好对齐；
- 区分模型、搜索、RAG、微调和聊天产品；
- 解释工具与权限怎样改变模型的实际能力。

## 原始基础模型只关心“合理后文”

预训练语言模型在海量文字与代码上完成预测任务。它能学习语言、知识模式、文体、代码结构和一定的上下文学习能力，但并不天然知道用户希望它：

- 直接回答问题；
- 按指定格式输出；
- 承认不知道；
- 避免危险建议；
- 使用清晰、礼貌的表达。

如果用户输入“如何种一棵番茄”，原始模型可能继续写成论坛对话、广告、小说或问题本身，而不是一份可靠步骤。

想象你从旧网页中截下一行：

> 用户：如何种一棵番茄？
>
> 网友甲：

基础模型学到的任务是“后面通常出现什么”，它可能接着写“先买我的营养液”，也可能模仿网友争论。文字可能很像互联网，却没有人明确教它：这里应该直接帮助提问者。

这好比一个读过许多书、很会续写故事的人，并不天然知道现在是在上课、写报告还是做客服。要成为助手，模型还要学习任务形式、人的偏好和安全边界。

## 从基础模型到助手的几个阶段

![预训练、指令微调、偏好对齐和产品系统共同形成AI助手](/course-assets/large-models/training-stages.svg)

### 预训练：形成广泛基础能力

模型在大规模数据上学习 Token 预测，获得通用表示。这个阶段成本最高，得到的是基础模型。

训练数据通常还要经历过滤、去重、质量控制和混合比例设计。网页数量多不代表应该让低质量网页占据训练主体。

### 监督式指令微调（SFT）：学习怎样完成任务

训练者准备“指令—优质回答”示例，让模型学习：

- 怎样回答问答、摘要、翻译和写作任务；
- 怎样遵守长度、语气和格式要求；
- 怎样把复杂问题拆成清晰步骤；
- 怎样在信息不足时追问或说明假设。

### 偏好对齐：学习哪些回答更符合人的要求

同一问题可能有多个语法正确答案。人们可以比较候选回答，训练奖励模型或直接优化偏好，使输出更有帮助、更安全、更符合产品规则。

常见路线包括基于人类反馈的强化学习（RLHF）和直接偏好优化（DPO）。它们不是把“全人类价值观”一次性写进模型，而是在特定数据、标注指南和产品目标下进行调整。

### 安全训练与红队评估

开发者还会测试模型面对危险请求、隐私信息、欺骗、提示注入和越权操作时的行为。安全是持续过程：新工具、新语言和新使用场景都可能出现新问题。

### 同一个提示，经过四个阶段会怎样变化

继续使用同一个问题：

> 请告诉一个第一次种植的中学生，怎样在阳台花盆里种番茄。请分步骤，并提醒常见失败原因。

下面不是某个真实产品的逐字输出，而是为了展示训练与系统设计的差别：

| 阶段 | 可能出现的行为 | 发生了什么变化 |
| --- | --- | --- |
| 只有预训练的基础模型 | 可能续写成论坛帖子，也可能给出没有结尾的段落 | 会生成语言，但不稳定地服从任务 |
| 经过 SFT | 按“选盆—播种—浇水—光照—支架”列出步骤 | 从优质指令示例中学会回答方式 |
| 经过偏好与安全对齐 | 语言更清楚，提醒不要误食农药，并在品种或气候不明时说明假设 | 学习人更偏好的帮助方式和边界 |
| 接入天气、日历等工具 | 在获得城市授权后查看近期气温，给出播种时间建议 | 外部工具补充了实时信息和精确操作 |

最后一行的“查看气温”不是参数突然变多了。系统把天气工具提供给模型，模型决定何时调用，工具返回数据，模型再组织回答。若城市没有授权、天气服务失败或数据日期过期，助手应说明限制，而不是假装已经查询成功。

同理，一个经过 SFT 的小模型可能比一个未经指令训练的大基础模型更适合作助手。评价产品不能只看模型多大，还要看它经历了什么训练、连接了什么系统，以及怎样处理错误。

## 模型、提示词、检索和微调有什么区别

| 方法 | 改变了什么 | 适合解决什么 | 不擅长解决什么 |
| --- | --- | --- | --- |
| 提示词 | 当前上下文 | 临时说明任务、格式和示例 | 不会永久修改模型参数 |
| RAG / 检索 | 给模型补充外部资料 | 更新知识、使用指定文档、提供来源 | 检索错了仍可能答错 |
| 微调 | 修改部分或全部参数 | 稳定风格、格式、领域行为或专门能力 | 不是实时更新事实的最佳方法 |
| 工具调用 | 允许执行外部函数 | 搜索、计算、代码、数据库和软件操作 | 权限、工具错误会带来新风险 |
| 更换模型 | 底层能力与成本 | 任务超出现有模型能力时 | 更大模型也不保证事实正确 |

### RAG 的简化流程

> 用户问题 → 在资料库中检索相关片段 → 把片段放进上下文 → 模型根据问题和片段回答

RAG 可以让答案基于指定资料，并提供可核验来源。但仍要检查：

- 检索是否漏掉关键资料；
- 片段是否过时或断章取义；
- 模型是否忠实使用片段；
- 引用是否真的支持结论。

### 学校手册问答：一次完整的 RAG 案例

假设学校发布了新版《图书馆借阅手册》，其中写着：

> 普通图书借期为 21 天；到期前可以续借一次，已经被其他同学预约的图书不能续借。

小林问助手：“图书可以借多久？我能一直续借吗？”

如果只依靠模型参数，它可能根据别的学校规定回答“30 天，可以续借两次”。语句很自然，但对这所学校是错的。RAG 系统会做下面几步：

1. 把问题转换成适合检索的表示；
2. 在学校授权的资料库中找到包含“借期、续借、预约”的片段；
3. 把片段连同文件名、发布日期一起放进模型上下文；
4. 要求模型只依据片段回答，并标出出处；
5. 返回：“普通图书借 21 天，可续借一次；若已被预约则不能续借。”

这时仍不能宣布“用了 RAG 就绝不会错”。检索系统可能找到了去年的旧手册；扫描 PDF 时可能把“21”识别成“27”；模型也可能漏掉“被预约不能续借”的条件。更可靠的界面应该让读者能打开原文，并显示版本和日期。

可以把几种方法记成不同的修理工具：

- 临时告诉助手“用三句话回答”——改提示词；
- 让它使用今天发布的学校手册——用 RAG；
- 让它长期稳定输出学校规定的 JSON 格式——可考虑微调；
- 让它计算逾期天数——调用计算器或代码；
- 让它真的替你续借——还要有图书馆工具、登录授权和确认步骤。

## “聊天产品”由多个系统组成

日常使用的 AI 助手可能包括：

- 基础模型；
- 系统指令和对话模板；
- 输入与输出安全检查；
- 搜索和知识库；
- 计算器、代码执行器和其他工具；
- 用户授权的记忆与存储；
- 速率限制、日志和人工审核；
- 文字、语音、图片与文件界面。

因此两个使用同一底层模型的产品，也可能因为搜索、提示、工具和权限不同而表现不同。

当你在界面上看到一个完整回答时，可以反向追问：

```text
这句话来自模型已有模式吗？
        ├─ 还是来自刚刚检索到的资料？
        ├─ 数字是否由计算器算出？
        ├─ 用户偏好是否由记忆系统提供？
        └─ 哪些内容被安全规则过滤或要求确认？
```

真实产品往往把这些环节无缝连接，所以使用者容易把整个系统的能力都归给“模型的大脑”。学会拆开它们，才能在答案出错时找到应该检查的位置。

## 对齐的难点

### 人的偏好并不完全一致

同一个回答，有人喜欢简洁，有人希望详细；不同文化、年龄和场景对合适表达也有差异。

### “看起来友好”不等于事实更可靠

偏好训练可能改善语气，却不能自动补齐精确事实。过度自信、讨好用户或迎合错误前提仍需要专门评估。

### 拒绝也可能出错

安全模型可能放过危险请求，也可能误拒绝正常的教育、新闻或健康信息。安全设计需要在风险与正当使用之间持续校准。

### 对齐不是“把正确答案装进去”

偏好标注者可能更喜欢条理清楚、自信完整的回答。如果评价流程没有同时认真检查事实，模型就可能学会“更像一个可靠助手”，却没有变得同样可靠。一个语气温和、格式漂亮的错误答案，仍然是错误答案。

人的偏好还会随场景变化。写生日贺卡时，活泼和想象力很重要；解释实验安全时，准确和谨慎更重要；遇到信息不足的问题，最有帮助的行为可能是先提问，而不是立刻输出一页文字。

所以对齐目标不应只是“让更多人点喜欢”，还要分别评估是否遵循要求、是否诚实表达不确定、是否安全、是否尊重不同群体，以及是否能在工具失败时停下来。

## 小练习：选择正确的改进方法

为下面问题选择“改提示、加 RAG、微调、加工具或换模型”，并说明理由：

1. 公司助手总是不知道昨天更新的内部制度；
2. 模型知道内容，却常把结果输出成错误 JSON 格式；
3. 模型需要计算 3791 × 8427；
4. 客服回答需要长期保持统一语气；
5. 系统要发送退款，但金额超过 100 元必须人工确认。

第 5 项不能只回答“加工具”，还必须设计权限和确认流程。

### 参考思路

1. **加 RAG。** 内部制度更新很快，应检索最新版并显示出处，而不是期待参数每天重新训练。
2. **先改提示或使用结构化输出约束；仍不稳定时再考虑微调。** 问题是输出格式，不一定需要更大的模型。
3. **加计算工具。** 精确乘法应交给可验证的计算器或代码，并回显结果。
4. **微调或使用稳定的系统指令与示例。** 若需要在大量场景中长期保持统一风格，微调可能比每次写很长提示更稳定。
5. **工具 + 权限设计。** 模型可以准备退款草稿，但超过 100 元时必须显示金额、对象和原因，由授权人员确认后才能执行。

这些题不总有唯一答案。好的选择要同时说明“为什么适合”和“它仍解决不了什么”。

## 本课小结

- 预训练形成广泛模式，指令微调让模型更会做任务；
- 偏好对齐改善有用性与安全性，但不是永远正确的保证；
- 提示、RAG、微调和工具解决不同问题；
- 真实聊天助手是模型与多种产品系统的组合。
