# 大模型：术语表、发展脉络与参考资料

## 核心术语速查

遇到陌生词时，不必从头背完整张表。先判断它属于哪一组：

| 术语组 | 它在回答什么问题 | 代表词 |
| --- | --- | --- |
| 输入与表示 | 文字、图片怎样变成可计算的数字？ | Token、词表、嵌入、位置表示 |
| 网络计算 | 信息怎样在模型内部交换和变换？ | 自注意力、Q/K/V、Transformer、激活 |
| 训练与对齐 | 模型怎样获得基础能力并更会服从任务？ | 预训练、SFT、RLHF、DPO |
| 生成与效率 | 下一步怎样选，运行成本怎样降低？ | logits、softmax、温度、量化、KV 缓存 |
| 产品与工具 | 模型之外还有哪些系统？ | RAG、工具调用、Agent、记忆 |
| 多模态与行动 | 图片、视频和动作怎样进入同一系统？ | 扩散、潜在空间、世界模型、VLA |
| 风险与核验 | 为什么会错，怎样验证和限制行动？ | 幻觉、grounding、最小权限、内容凭证 |

正文第一次遇到术语时应先读故事和例子，这一页用于回查。术语的一句话解释是入口，不是完整机制。

| 术语 | 一句话解释 |
| --- | --- |
| 大语言模型（LLM） | 在大规模文字与代码数据上训练、用于处理语言序列的模型 |
| 基础模型 | 先广泛预训练，再适配许多下游任务的通用起点 |
| Token | 模型处理序列的基本单位，可以是词、子词、字或符号 |
| 词表 | 分词器可识别 Token 与 ID 的映射集合 |
| 嵌入（embedding） | 把离散 Token 转换为高维向量表示 |
| 位置表示 | 告诉模型 Token 的顺序与相对距离 |
| 自注意力 | 让序列中每个位置按相关程度汇总其他位置的信息 |
| Query / Key / Value | 注意力中的查询、匹配键和被汇总内容 |
| Transformer | 以注意力和前馈网络为核心的序列模型架构 |
| 因果遮罩 | 禁止生成模型在训练时偷看未来 Token |
| 自回归生成 | 把刚生成的结果接回上下文，再预测下一步 |
| 上下文窗口 | 模型一次计算能够处理的 Token 范围 |
| SFT | 使用指令—优质回答示例进行监督式微调 |
| RLHF | 利用人类反馈训练奖励与策略，使输出更符合偏好 |
| DPO | 直接利用偏好对比较优化模型的方法 |
| RAG | 先检索外部资料，再把相关片段提供给模型回答 |
| MoE | 每个 Token 只激活部分专家模块的混合专家架构 |
| 扩散模型 | 学习从噪声状态逐步恢复或生成数据的模型 |
| 潜在空间 | 模型学习到的压缩数字表示空间 |
| 多模态模型 | 共同处理文字、图像、声音、视频等信息的模型 |
| Agent | 连接模型、工具、状态和任务循环以连续行动的系统 |
| 世界模型 | 学习状态随动作和时间如何变化的模型 |
| VLA | 从视觉、语言和机器人状态生成动作的模型 |
| 幻觉 | 流畅但与事实或输入不一致的生成内容 |

### 补充术语：读技术说明时常见

| 术语 | 一句话解释 | 容易混淆的地方 |
| --- | --- | --- |
| logits | 模型对词表候选给出的原始分数 | 还不是总和为 100% 的概率 |
| softmax | 把一组分数转换成概率分布的函数 | 概率高表示更符合当前模式，不保证事实为真 |
| 推理（inference） | 训练完成后，模型根据新输入产生输出的过程 | 这里的“推理”有时仅指运行模型，不一定表示复杂逻辑推导 |
| 激活（activation） | 网络处理当前输入时产生的中间数值 | 不等于 MoE 中“激活参数量”的全部含义，但两者相关 |
| KV 缓存 | 生成时保存旧 Token 的 Key 和 Value，减少重复计算 | 能提速，但会占内存，也不会提供永久记忆 |
| 量化 | 用较低精度表示权重或计算，以减少存储和成本 | 压缩后仍需评估质量、速度和硬件兼容性 |
| 温度 | 调整候选概率分布平坦或集中的生成设置 | 高温度增加多样性，不等于增加真正创造力或知识 |
| Top-p | 只在累计概率达到阈值的一小组候选中采样 | 与温度作用不同，常组合使用 |
| grounding（依据约束） | 让回答明确依赖给定资料、环境或工具结果 | 有依据仍需检查依据本身是否正确和是否被忠实使用 |
| 提示注入 | 外部内容试图把自己伪装成指令，诱导系统偏离原任务 | 网页上的命令文字不等于用户授权 |
| 最小权限 | 只授予完成当前任务真正需要的数据和动作权限 | 模型更强不代表应该获得更多权限 |
| 内容凭证 | 记录数字内容来源和编辑过程的可验证信息 | 没有凭证不自动等于伪造，有凭证也要核对签发者 |

### 相近概念不要混在一起

- **Token 与 Token ID：** Token 是序列单位，ID 是它在词表中的地址。
- **模型参数与产品记忆：** 参数通过训练形成；聊天记忆通常保存在模型外。
- **总参数与激活参数：** MoE 可以拥有很大总容量，但每个 Token 只调用其中一部分。
- **基础模型与 AI 助手：** 前者是训练得到的核心网络，后者还包含对齐、指令、检索、工具和界面。
- **聊天模型与 Agent：** 前者主要生成回答，后者在任务循环中调用工具并采取行动。
- **生成得逼真与事情真实发生：** 视觉质量不能替代来源证明。

## 一条简化的发展脉络

| 时间 | 代表进展 | 关键意义 |
| --- | --- | --- |
| 20 世纪至 21 世纪初 | 统计语言模型 | 用词频与局部上下文估计下一个词 |
| 2003 前后 | 神经概率语言模型 | 用向量和神经网络表示词语关系 |
| 2017 | Transformer | 用自注意力建立上下文联系并支持并行训练 |
| 2018 | GPT、BERT | 大规模预训练后再适配任务成为主线 |
| 2019—2020 | GPT-2、GPT-3 | 上下文学习与少样本能力受到广泛关注 |
| 2022 | InstructGPT、ChatGPT | 指令对齐与对话界面让大模型进入大众使用 |
| 2023 以后 | 多模态、工具、推理与 Agent | 从文字生成扩展到感知、工具使用和任务执行 |
| 持续发展中 | VLA、世界模型与 Physical AI | 模型开始连接机器人和物理环境 |

这条时间线不是“模型突然觉醒”的故事。每一步都依赖数据、算力、架构、训练方法和产品设计的长期积累。

### 七幕发展史索引

把这条长历史看成七幕连续故事，会比背年份更容易理解：

1. **先学会统计接龙。** 早期语言模型根据词频和有限上下文猜下一个词，“祝你生日”后面常接“快乐”。它们能处理常见搭配，却难以保存很长的前文。
2. **词语进入神经网络。** 神经概率语言模型把词转换成向量，让相似用法可以共享参数；RNN 和 LSTM 继续尝试携带历史信息，但顺序计算限制了大规模并行。
3. **Transformer 修建高速公路。** 2017 年，自注意力让远距离位置直接建立联系，也让许多位置能在训练时并行计算。它最初服务于翻译，后来扩展到语言、视觉、语音和机器人。
4. **先广泛预训练，再适配任务。** 2018 年前后的 GPT 与 BERT 证明，同一个模型可以先从海量通用文字中学习，再用于问答、分类、翻译等任务。
5. **提示词变成任务接口。** GPT-2、GPT-3 等规模化模型展示了零样本、少样本和上下文学习：不修改参数，只在提示中描述任务或给少量示例，也能完成新任务。
6. **会续写变成会帮助。** 指令微调、人类偏好训练和聊天界面让模型更愿意直接回答、遵守格式并处理对话。ChatGPT 让这组技术在 2022 年进入大众视野，但并非那一天才突然发明大模型。
7. **从文字走向多模态和行动。** 模型开始连接图片、声音、视频、搜索、代码和软件工具；Agent 处理多步任务，VLA 与世界模型进一步把语言和视觉连接到物理行动。

每一幕都解决了旧问题，也带来新问题：上下文更长会增加计算，工具扩大能力也扩大权限风险，多模态更逼真也让真假更难辨认。历史不是“越来越像人”的单线比赛，而是架构、数据、训练、系统和治理共同变化。

### 怎样选择下面的资料

本页把资料分成三种难度：

- **入门：** 有动画、图解或较少公式，适合先建立直觉；
- **进阶：** 官方教程或课程，需要耐心阅读概念和少量代码；
- **研究：** 原始论文或技术报告，适合查证提出了什么方法、实验怎样设计。

“一手来源”指论文、官方技术报告、模型卡或标准组织原文。它更接近事实起点，但不一定最容易读；高质量图解适合学习，却不应替代一手来源来证明精确参数、日期和实验数字。

## Agent、机器人与风险治理

ReAct、Toolformer、RT-2 和 OpenVLA 分别代表推理与行动、工具学习、视觉—语言—动作等研究方向；NIST 框架讨论的是风险治理，而不是某个模型结构。不要因为它们都出现在“Agent”栏目，就把工具调用、机器人控制和治理标准当成同一个概念。

### 查证模型规模与资源数字时优先找什么

1. 模型开发团队发布的技术报告或模型卡；
2. 论文中的训练设置、硬件表和附录；
3. 数据中心或企业可持续发展报告中的统计口径；
4. 研究资源消耗的论文，并确认它写的是实测还是估算；
5. 新闻和社交媒体只作为线索，再回到上述来源。

记录数字时同时抄下日期、单位和边界。例如“GPU 小时”还要写芯片型号；参数量要区分总参数和激活参数；用水要区分地点、冷却方式、取水与耗水。官方没有公开时，最准确的答案就是“未公开”，不能用网络传言补空格。

## 用八个问题结束这一章

以后遇到一个新模型或 AI 产品，先问：

1. 输入和输出模态是什么？
2. 核心训练目标是什么？
3. 参数是否公开，是稠密还是 MoE？
4. 训练数据和更新时间公开到什么程度？
5. 回答时是否使用搜索、数据库、代码或其他工具？
6. 结果怎样核验，引用是否直接支持结论？
7. 系统被允许读取什么、发送什么、执行什么？
8. 资源消耗、错误后果与最终责任由谁承担？

理解大模型的意义不是背出每个模型名称，而是建立一套长期有效的判断方法：知道能力从哪里来，也知道哪里必须停下来查证、授权和负责。
