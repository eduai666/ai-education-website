# 大模型：术语表、发展脉络与参考资料

## 核心术语速查

| 术语 | 一句话解释 |
| --- | --- |
| 大语言模型（LLM） | 在大规模文字与代码数据上训练、用于处理语言序列的模型 |
| 基础模型 | 先广泛预训练，再适配许多下游任务的通用起点 |
| Token | 模型处理序列的基本单位，可以是词、子词、字或符号 |
| 词表 | 分词器可识别 Token 与 ID 的映射集合 |
| 嵌入（embedding） | 把离散 Token 转换为高维向量表示 |
| 位置表示 | 告诉模型 Token 的顺序与相对距离 |
| 自注意力 | 让序列中每个位置按相关程度汇总其他位置的信息 |
| Query / Key / Value | 注意力中的查询、匹配键和被汇总内容 |
| Transformer | 以注意力和前馈网络为核心的序列模型架构 |
| 因果遮罩 | 禁止生成模型在训练时偷看未来 Token |
| 自回归生成 | 把刚生成的结果接回上下文，再预测下一步 |
| 上下文窗口 | 模型一次计算能够处理的 Token 范围 |
| SFT | 使用指令—优质回答示例进行监督式微调 |
| RLHF | 利用人类反馈训练奖励与策略，使输出更符合偏好 |
| DPO | 直接利用偏好对比较优化模型的方法 |
| RAG | 先检索外部资料，再把相关片段提供给模型回答 |
| MoE | 每个 Token 只激活部分专家模块的混合专家架构 |
| 扩散模型 | 学习从噪声状态逐步恢复或生成数据的模型 |
| 潜在空间 | 模型学习到的压缩数字表示空间 |
| 多模态模型 | 共同处理文字、图像、声音、视频等信息的模型 |
| Agent | 连接模型、工具、状态和任务循环以连续行动的系统 |
| 世界模型 | 学习状态随动作和时间如何变化的模型 |
| VLA | 从视觉、语言和机器人状态生成动作的模型 |
| 幻觉 | 流畅但与事实或输入不一致的生成内容 |

## 一条简化的发展脉络

| 时间 | 代表进展 | 关键意义 |
| --- | --- | --- |
| 20 世纪至 21 世纪初 | 统计语言模型 | 用词频与局部上下文估计下一个词 |
| 2003 前后 | 神经概率语言模型 | 用向量和神经网络表示词语关系 |
| 2017 | Transformer | 用自注意力建立上下文联系并支持并行训练 |
| 2018 | GPT、BERT | 大规模预训练后再适配任务成为主线 |
| 2019—2020 | GPT-2、GPT-3 | 上下文学习与少样本能力受到广泛关注 |
| 2022 | InstructGPT、ChatGPT | 指令对齐与对话界面让大模型进入大众使用 |
| 2023 以后 | 多模态、工具、推理与 Agent | 从文字生成扩展到感知、工具使用和任务执行 |
| 持续发展中 | VLA、世界模型与 Physical AI | 模型开始连接机器人和物理环境 |

这条时间线不是“模型突然觉醒”的故事。每一步都依赖数据、算力、架构、训练方法和产品设计的长期积累。

## 用八个问题结束这一章

以后遇到一个新模型或 AI 产品，先问：

1. 输入和输出模态是什么？
2. 核心训练目标是什么？
3. 参数是否公开，是稠密还是 MoE？
4. 训练数据和更新时间公开到什么程度？
5. 回答时是否使用搜索、数据库、代码或其他工具？
6. 结果怎样核验，引用是否直接支持结论？
7. 系统被允许读取什么、发送什么、执行什么？
8. 资源消耗、错误后果与最终责任由谁承担？

理解大模型的意义不是背出每个模型名称，而是建立一套长期有效的判断方法：知道能力从哪里来，也知道哪里必须停下来查证、授权和负责。
