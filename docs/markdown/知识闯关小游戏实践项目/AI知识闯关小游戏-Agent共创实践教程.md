# AI 知识闯关小游戏：和 Agent 共创的手把手实践教程

## 项目信息

| 项目 | 内容 |
| --- | --- |
| 项目名称 | AI 知识闯关小游戏 |
| 推荐年级 | 小学高年级至初中 |
| 建议用时 | 5—8 课时，每课时 40—45 分钟 |
| 编程基础 | 不要求；你需要愿意阅读、测试和说明问题 |
| 推荐工具 | Codex 桌面版或 WorkBuddy 桌面版 |
| 运行方式 | 在浏览器中打开本地网站 |
| 知识范围 | 本网站“AI 基础课程”前四个单元 |
| 最终入口 | `/projects/learn/ai-knowledge-challenge` |
| 是否需要外部 API | 游戏运行不需要；Agent 只在开发阶段帮助修改本地项目 |

这不是一份“复制一段神奇提示词，马上得到成品”的教程。你会把一个较大的想法拆成许多可以检查的小任务，再和 Agent 一轮一轮地完成。

Agent 可以搜索项目、修改文件、运行检查和解释代码。你负责决定目标、限制和完成标准，也要亲自试玩、核验题目、指出问题并确认最终结果。

整个过程可以记成：

> **想清楚 → 拆小任务 → 说清要求 → 查看改动 → 运行测试 → 描述问题 → 局部修改 → 再次核验**

## 最终作品是什么样

本教程对应的正式示例作品具有以下规则：

- 题库共有 20 道单选题，前四个 AI 基础单元各 5 道；
- 每一轮从每个单元随机抽取 3 道，共 12 道，保证四个单元都会出现；
- 每道题固定有 4 个选项，并且只有一个最佳答案；
- 选择答案后立即锁定本题，显示正误、正确答案和解释；
- 未作答时不能进入下一题，作答后可以继续；
- 可以回到已经答过的上一题查看答案，但不能反复作答刷分；
- 最后一题完成后显示百分制总分和四个单元的表现；
- 结果页提供错题回顾，列出玩家答案、正确答案、解释和课程来源；
- “重新随机挑战”会重置本轮状态，并重新抽取题目；
- 浏览器只在本机保存最高百分比，不收集姓名、账号等信息；
- 电脑、平板和手机上都能使用，也支持键盘和读屏软件的基本操作。

> [!NOTE]
> 这里把规则写得具体，是为了让“完成”能够被检查。你制作自己的版本时，可以更换题量、主题和风格，但每次只能修改少数规则，并同步更新验收标准。

## 你将在项目中学会什么

完成项目后，你应当能够：

1. 把“做一个好玩的游戏”改写成可以执行和检查的小任务；
2. 向 Agent 说明目标、项目范围、不能改什么和怎样算完成；
3. 区分 Agent 的计划、实际文件改动、命令结果和口头说明；
4. 运行网站，并用真实操作判断功能是否正确；
5. 用“操作—预期—实际—范围”描述一个程序问题；
6. 要求 Agent 只修改受影响的部分，并进行回归测试；
7. 根据课程原文核验题目、答案、解释和知识来源；
8. 检查随机抽题、计分、错题回顾与重玩是否保持一致；
9. 使用手机尺寸、键盘和读屏提示检查可访问性；
10. 说明作品中哪些决定由你作出，哪些工作由 Agent 协助完成。

## Codex 和 WorkBuddy 的共同操作原则

两种工具的按钮名称和界面可能不同，但共创方法相同。

### 先打开正确的项目文件夹

开始前确认 Agent 的工作区就是练习项目，而不是桌面、整个用户目录或其他重要文件夹。本项目的示例工作区是 `D:\web_ai_project`。

发送任务前，先让 Agent 复述当前项目路径和它准备接触的文件范围。路径不对就停止，不要继续。

### 先读项目规则，再动文件

项目可能有 `AGENTS.md`、`README.md` 或其他开发说明。先让 Agent 阅读这些规则，并查看已有页面、组件和测试方式。不要凭别的项目经验直接套代码。

### 一轮只解决一个主要问题

“增加错题回顾”和“重做整个界面”是两项任务。把它们放在同一轮，出现错误时很难判断原因。

每轮都先写清：本次改什么、不改什么、怎样验收。完成后检查，再进入下一轮。

### 看证据，不只听结论

Agent 说“已经完成”只是报告，不是证据。你至少要查看：

- 哪些文件发生了变化；
- 实际运行了哪些检查；
- 检查输出是否成功；
- 浏览器里的真实操作是否符合要求；
- 有没有还没解决的问题或假设。

### 权限从小到大

第一次让 Agent 只读项目并提出计划。需要修改时再开放当前练习项目的写入权限。删除文件、安装软件、访问账号、发布网站或推送代码，应作为单独步骤确认。

不要在提示词、截图、代码或聊天记录中粘贴 API Key、密码、验证码和个人信息。

## 写提示词，不是背提示词

下面每个阶段都会提供一段示例提示词。示例的作用是展示**信息结构**，不是要求逐字照抄。

一份适合开发任务的提示词通常包含六格：

| 信息 | 要回答的问题 | 例子 |
| --- | --- | --- |
| 背景 | Agent 正在什么项目里工作？ | 这是一个已有的中文 AI 教育网站 |
| 目标 | 这一轮只完成什么？ | 建立可运行的最小游戏页面 |
| 范围 | 可以查看或修改哪里？ | 游戏功能目录和对应页面 |
| 限制 | 哪些事情不要做？ | 不接登录，不改其他课程，不推送 Git |
| 验收 | 什么现象证明完成？ | 能完成一轮答题并重新开始 |
| 证据 | Agent 最后要报告什么？ | 文件清单、检查命令、结果和遗留问题 |

如果提示词写得很长，却没有范围和完成标准，仍然可能很模糊。反过来，一段不长但边界清楚的提示词，往往更有效。

## 第 0 阶段：建立安全的练习环境

### 这一步要告诉 Agent 哪些信息

- 当前项目的准确路径；
- 这一轮只允许阅读，不修改文件；
- 需要找到项目规则、运行方式和可能的游戏接入位置；
- 不安装软件、不启动发布、不提交 Git。

### 示例提示词

```text
请先只读检查当前项目，不要修改任何文件。

请确认当前工作目录，阅读项目中的 AGENTS.md 和 README，找出：
1. 这个网站使用的技术和目录结构；
2. 本地怎样运行和检查；
3. 新增“AI知识闯关小游戏”最可能涉及哪些文件；
4. 项目中有哪些现成布局、按钮或样式可以复用；
5. 哪些信息还不确定。

不要安装依赖，不要提交或推送。最后只给调查结果和建议计划。
```

### 学生要亲自检查什么

- Agent 复述的工作目录是否正确；
- 它有没有真的找到项目规则，而不是说“通常应该这样”；
- 它列出的目录是否在文件管理器中存在；
- 这一轮结束后是否没有文件改动。

### 完成标准

- 你能说出网站怎样运行，以及游戏会接到哪里；
- Agent 给出了基于当前项目的计划；
- 项目文件没有被修改。

## 第 1 阶段：把想法变成项目任务卡

### 这一步要告诉 Agent 哪些信息

先由你填写任务卡，再请 Agent 找遗漏。

| 设计问题 | 本教程的决定 | 我的版本 |
| --- | --- | --- |
| 游戏给谁使用 | 小学高年级和初中生 |  |
| 考察什么 | AI 基础前四单元 |  |
| 题库规模 | 20 题，每单元 5 题 |  |
| 每轮题数 | 每单元随机 3 题，共 12 题 |  |
| 必要功能 | 反馈、计分、前后题、结果、错题、重玩 |  |
| 不能加入 | 登录、联网排行、付费、个人信息收集 |  |
| 页面风格 | 清晰、有活力，不影响阅读 |  |
| 成功证据 | 自动检查通过，并完成桌面、手机和键盘试玩 |  |

### 示例提示词

```text
请把下面的游戏设想整理成开发任务清单，先不要写代码。

目标用户：小学高年级和初中生。
知识范围：本站 AI 基础课程前四单元。
最终规则：20题题库，每单元5题；每轮每单元随机抽3题，共12题。
必须功能：开始说明、逐题单选、即时解析、计分、上一题/下一题、结果页、分单元表现、错题回顾、重新随机挑战、最高百分比。
边界：不登录、不联网、不收集个人信息，不修改其他课程页面。

请把任务拆成可以分别验收的小阶段。每个阶段写清输入、输出、风险和完成标准，并指出合理的开发顺序。
```

### 学生要亲自检查什么

- 每个阶段是不是只解决一个主要问题；
- 题库准确性是否独立成一项任务；
- 响应式和无障碍是否进入计划，而不是最后随口补上；
- 有没有把“美观”错误地当成第一优先级。

### 完成标准

- 计划先跑通核心流程，再增加学习功能和视觉效果；
- 每个阶段都可以单独试玩或检查；
- 计划没有超出任务边界。

## 第 2 阶段：建立能跑通的最小版本

最小版本的目的不是一次完成全部功能，而是尽早证明“页面能打开、状态能向前走”。可以先放 4 道已经核验的题，每个单元 1 道。

### 这一步要告诉 Agent 哪些信息

- 游戏要接入已有网站，而不是另建一套不相关项目；
- 最小版只有开始、答题、反馈、下一题、结果和重玩；
- 先复用项目技术和样式，不增加新依赖；
- 只能修改游戏相关文件；
- 需要真实运行检查。

### 示例提示词

```text
现在实现“AI知识闯关小游戏”的最小可运行版本。

请遵守项目规则并复用现有技术。页面入口规划为
/projects/learn/ai-knowledge-challenge。

本轮只实现：开始页、4道单选题、作答反馈、下一题、最终答对数、重新开始。
每个单元暂放1道已核验题。暂时不做随机题库、错题回顾、最高分和动画。

不要修改其他课程内容，不增加登录或外部API，不安装不必要的依赖。
完成后运行与改动相匹配的检查，并报告改动文件、运行方法、检查结果和未完成项。
```

### 学生要亲自检查什么

1. 页面是否能打开；
2. 是否从开始页进入第一题；
3. 点击选项后是否出现反馈；
4. 是否能走到结果页；
5. 重新开始后题号和得分是否归零；
6. 其他课程页面是否仍能打开。

### 完成标准

- 你可以完整玩完一轮；
- 最基本的状态不会卡住或跳错；
- Agent 提供了实际检查结果，而不是只展示代码。

## 第 3 阶段：建立四单元准确题库

游戏的代码可以由 Agent 生成，题目的责任不能全部交给 Agent。正式题库要回到课程原文逐题核验。

### 这一步要告诉 Agent 哪些信息

每道题至少应包含：

- 唯一 `id`；
- 所属单元和单元名称；
- 清楚、没有多余前提的题干；
- 固定 4 个选项；
- 唯一最佳答案的位置；
- 解释“为什么正确、易错项错在哪里”的解析；
- 课程标题和课程页面链接。

20 道题可以围绕下面的知识检查点组织：

| 单元 | 5 个建议检查点 |
| --- | --- |
| 认识人工智能 | 自动运行不等于 AI；训练与推理；下一 Token；上下文不是永久记忆；模型、工具和人的责任 |
| 机器学习与深度学习 | 样本/特征/标签；监督/无监督/强化学习；权重/偏置/激活；损失/反向传播/优化器；训练集/验证集/测试集与泛化 |
| 大模型是如何工作的 | “大”不只看参数；Token 与 Token ID；Query/Key/Value；自回归生成；基础模型、RAG、工具和 Agent 的区别 |
| 什么是智能体 | 智能体是一套系统；状态与上下文；观察—判断—行动—检查；固定工作流与智能体；停止条件和最小权限 |

优先使用这些课程原文：

- [认识人工智能](../01-认识人工智能/01-人工智能就在我们身边.md)
- [机器学习与深度学习](../机器学习与深度学习/00-章节导读.md)
- [大模型是如何工作的](../大模型是如何工作的/00-章节导读.md)
- [什么是智能体](../04-什么是智能体/00-单元导读.md)

### 示例提示词

```text
请为游戏整理正式题库，但先把内容准确性放在代码之前。

请完整阅读本站 AI 基础课程前四单元。题库共20题，每单元5题。
每题需要 id、单元、题干、4个选项、唯一正确答案、适合学生阅读的解析，以及具体课程来源。

规则：
1. 不从网络随意补充课程没有讲过的冷知识；
2. 不使用“总是、一定、完全”等会造成错误绝对化的说法；
3. 干扰项要看起来合理，但不能出现两个都正确；
4. 解析不能只写“答案是B”，要解释判断依据；
5. 先输出题目审查表，标明每题对应的课程段落，再写入题库；
6. 发现课程无法支持的题目时，删除或改题，不要猜测。

完成后检查题目数量、单元平衡、ID唯一、选项数量和答案范围。
```

### 学生要亲自检查什么

为 20 道题逐项填写：

| 检查项 | 通过标准 |
| --- | --- |
| 题干 | 不靠猜测隐藏前提也能理解 |
| 答案 | 课程原文能直接支持，且只有一个最佳答案 |
| 干扰项 | 错得有理由，不靠错别字或荒唐表达送分 |
| 解析 | 解释概念，并提醒最容易混淆的地方 |
| 来源 | 链接到真正支持本题的课程，而不是单元首页占位 |
| 难度 | 小学高年级或初中生读得懂，不考无意义参数记忆 |

最好请同学或老师再做一次独立审题。同一个 Agent 检查自己刚生成的题目，不能代替外部核验。

### 完成标准

- 恰好 20 道题，四个单元各 5 道；
- 每题 4 个选项，正确答案位置有效；
- 每个 ID 唯一；
- 每道题都有准确解析和可打开的课程来源；
- 人工审题表全部完成。

## 第 4 阶段：完成单题作答与即时反馈

### 这一步要告诉 Agent 哪些信息

- 玩家点击一个选项后，本题立即锁定；
- 同一题不能通过重复点击增加得分；
- 正确和错误都要有文字反馈，不能只靠颜色；
- 作答后显示正确答案、解析和课程来源；
- 玩家主动点击“下一题”，不要自动跳走。

### 示例提示词

```text
请只完善单题作答和反馈，不改题库内容、随机规则或整体视觉。

要求：每题只能作答一次；点击后锁定全部选项；明确显示“回答正确”或“回答错误”；同时显示正确答案、解析和课程来源；不要自动进入下一题。快速连续点击也不能重复计分。

请为重复点击和未作答状态补充检查。完成后说明新增或修改了哪些状态，以及怎样证明每题只能计分一次。
```

### 学生要亲自检查什么

- 连续快速点击两个选项，分数是否只变化一次；
- 答错时是否清楚显示玩家选择和正确答案；
- 只看文字、不看颜色时，能否分辨正误；
- 解析是否留在页面上，直到玩家主动继续；
- 来源是否能打开到相关课程。

### 完成标准

- 每题只记录一次答案；
- 反馈、解析和来源都与当前题对应；
- 下一题不会在玩家阅读解析前自动出现。

## 第 5 阶段：完成计分和前后题流程

### 这一步要告诉 Agent 哪些信息

- 顶部显示当前题号和总题数；
- 未作答时“下一题”不可用；
- 作答后才允许前进；
- 第二题开始可以返回上一道已答题；
- 返回后保留原选择、反馈和得分，不重新计分；
- 最后一题按钮改成“查看结果”。

### 示例提示词

```text
请只实现进度、计分和上一题/下一题流程。

规则：本轮12题；每题只能贡献一次正确数；未作答不能下一题；可以返回已答的上一题查看；返回后答案保持锁定，不能改答案或重复得分；最后一题作答后进入结果页。

请把“当前显示位置”“玩家答案”“已答状态”和“得分”分开管理，避免返回上一题时破坏状态。补充全对、全错和混合答案的测试。
```

### 学生要亲自检查什么

至少完成三轮：

1. 全部答对，最终应为 100%；
2. 全部答错，最终应为 0%；
3. 一半答对，手工计算结果并与页面比较。

另外测试：未答就点下一题、答完返回上一题、来回切换三次、末题进入结果页。

### 完成标准

- 进度显示和当前题一致；
- 分数与手工计算一致；
- 前后切换不丢答案、不重复计分；
- 第一题没有无意义的“上一题”，末题流程正确结束。

## 第 6 阶段：制作最终结果和分单元表现

### 这一步要告诉 Agent 哪些信息

- 显示答对数、总题数和百分比；
- 分别显示四个单元本轮答对几题；
- 根据表现给出鼓励和复习建议，不给学生贴“聪明/不聪明”标签；
- 本机保存历史最高百分比；
- 新成绩更低时不能覆盖最高分；
- 不上传成绩，不保存姓名。

### 示例提示词

```text
请增加结果页和本地最高分，不修改作答规则与题库。

结果页显示答对数、12题总数、百分制得分，以及四个单元各自的答对数。根据需要复习的单元给出中性、具体的学习建议。

只用浏览器 localStorage 保存最高百分比，不保存姓名、作答明细或其他个人信息。浏览器不支持存储时，游戏仍要正常完成。请补充最高分更新规则的测试。
```

### 学生要亲自检查什么

- 总分是否由本轮答题计算，而不是写死；
- 四个单元每项的题目总数是否都是 3；
- 先得 80 分、再得 60 分，最高分是否仍为 80；
- 刷新页面后最高分是否仍存在；
- 清除网站本地数据后，游戏是否还能正常开始。

### 完成标准

- 总分、分单元表现和题目记录一致；
- 最高分只保存在当前浏览器；
- 存储失败不会让游戏崩溃；
- 页面没有收集个人信息。

## 第 7 阶段：加入错题回顾

### 这一步要告诉 Agent 哪些信息

- 结果页只列出本轮答错的题；
- 每道错题显示题干、玩家答案、正确答案、解析和课程来源；
- 全部答对时显示明确的“本轮没有错题”；
- 错题数量必须等于总题数减去答对数；
- 不要为了错题功能修改原题答案。

### 示例提示词

```text
请在现有结果页增加错题回顾，保持题库和计分逻辑不变。

错题回顾需要显示题干、玩家选择、正确答案、解析和课程来源。只显示本轮答错题；全对时显示“本轮没有错题”。请从已有作答记录计算错题，不另建一套可能不一致的答案数据。

请测试：全对、错1题、全错，以及返回上一题后再结束。
```

### 学生要亲自检查什么

- 故意答错一题，结果页是否只出现这一题；
- 玩家答案和正确答案是否没有调换；
- 全错时 12 道错题是否都出现且页面仍能滚动；
- 点击课程来源是否真的能帮助复习；
- 全对时是否没有空白区域或错误标题。

### 完成标准

- 错题数量和总分严格对应；
- 每条错题信息完整、顺序清楚；
- 全对和全错两种边界情况都能正常显示。

## 第 8 阶段：加入均衡随机与重新挑战

只把 20 道题整体打乱后取前 12 道，可能让某个单元一题也没有。这里要先按单元分组，再从每个单元随机抽 3 道。

### 这一步要告诉 Agent 哪些信息

- 每轮必须恰好 12 道；
- 四个单元各 3 道；
- 同一道题一轮内不能重复；
- “重新随机挑战”重新抽题，并清空本轮答案、进度和分数；
- 最高分保留；
- 随机算法不要直接修改原题库顺序。

### 示例提示词

```text
请实现均衡随机和重新挑战，只修改抽题与重置相关逻辑。

题库20题，每单元5题。每轮从四个单元分别随机抽3题，合并成12题并打乱展示顺序。同一轮不得重复，也不要原地修改永久题库。

重新挑战时重新抽题，并清空当前题号、作答记录、得分、反馈和错题；最高百分比继续保留。

请增加可重复运行的逻辑测试，验证每轮12题、每单元3题、ID不重复、原题库不被改变。
```

### 学生要亲自检查什么

- 连续重新挑战至少 5 次，记录每轮四单元题量；
- 每轮是否都是 3、3、3、3；
- 同一轮有没有重复题；
- 新一轮第一题是否保持上一轮的选中状态；
- 新一轮总分是否归零，而最高分是否保留。

### 完成标准

- 随机顺序会变化，但知识覆盖始终均衡；
- 重玩完整重置本轮状态；
- 自动测试能够大量重复抽题而不出现重复或单元缺失。

## 第 9 阶段：让页面在电脑和手机上都好用

### 这一步要告诉 Agent 哪些信息

- 保持网站原有视觉语言；
- 题干是视觉重点，选项容易点击；
- 长题干、长选项和解析都能自动换行；
- 手机上不出现横向滚动；
- 结果页错题很多时仍可正常阅读；
- 只调整游戏样式，不重做整个网站。

### 示例提示词

```text
请只优化游戏页面的排版和响应式样式，不改题库、计分、随机和路由。

目标用户是小学高年级和初中生。保持现有网站风格，建立清楚的标题、进度、题目、选项、反馈和操作层级。重点检查360px左右手机宽度、平板和桌面；长文字自动换行；按钮有足够点击区域；结果页与错题回顾不重叠、不横向溢出。

完成后列出测试过的视口尺寸和仍需注意的视觉问题。
```

### 学生要亲自检查什么

在浏览器开发者工具中至少查看：360×800、768×1024 和常见桌面宽度。检查长选项、全错结果页、页面缩放到 200% 和横竖屏变化。

### 完成标准

- 三类屏幕都没有遮挡、重叠或横向滚动；
- 文字层级清楚，按钮容易识别和点击；
- 放大文字后仍能完成整轮游戏。

## 第 10 阶段：完成键盘和无障碍检查

无障碍不是“最后加一个 aria 标签”。优先使用原生的按钮、单选题分组和进度元素，再补充必要提示。

### 这一步要告诉 Agent 哪些信息

- 不用鼠标也能完成游戏；
- 焦点位置清楚可见；
- 题目切换后焦点回到新题标题；
- 正误反馈能被读屏软件知道；
- 选项具有题组和标签关系；
- 禁用按钮的状态真实有效；
- 用户要求减少动画时关闭非必要动画；
- 不能只用红绿颜色表达正误。

### 示例提示词

```text
请对游戏做一次无障碍专项改进，不改变视觉主题和业务规则。

优先使用语义化原生元素：button、fieldset/legend、progress。确保 Tab 顺序合理、focus-visible 清楚、键盘能选择选项和操作按钮；题目切换后聚焦题目标题；正误反馈用 aria-live 或 role=status 通知；禁用状态可被读屏识别；支持 prefers-reduced-motion；任何正误都同时有文字和图形提示。

请说明每项改动解决了什么问题，并给出键盘人工测试步骤。
```

### 学生要亲自检查什么

拔掉鼠标或暂时不用触控板，只用 `Tab`、`Shift+Tab`、方向键、空格和回车完成一轮。观察焦点是否丢失、是否跳到不可见区域、反馈是否自动把页面带走。

如果电脑有读屏工具，可以试听题目、选项、已选状态、反馈和按钮名称。再打开“减少动态效果”设置，确认功能不依赖动画。

### 完成标准

- 只用键盘可以开始、答题、前进、回看、查看结果并重玩；
- 焦点始终可见且顺序符合页面阅读顺序；
- 读屏能知道当前题目、选项状态和正误反馈；
- 减少动画时不影响任何功能。

## 第 11 阶段：测试、描述问题和要求局部修复

### 先学会写问题报告

“游戏坏了”缺少定位信息。一个可复现的问题报告至少包含：

```text
环境：使用的页面、浏览器和窗口大小
操作：我按什么顺序做了什么
预期：按规则应该发生什么
实际：页面实际上发生了什么
频率：每次出现，还是偶尔出现
证据：截图、控制台错误或具体题目
范围：请只检查哪一部分，哪些内容不要改
```

例如：

```text
我在手机宽度360px下完成12题，其中答错4题。结果页显示8/12，但错题回顾只有3题。这个问题重复两次都会出现。

预期应显示4道错题。请先检查错题筛选是否与作答记录使用同一数据，不要改题库、随机抽题和页面配色。修复后补充一个“答错4题就返回4条错题”的测试，并重新运行相关检查。
```

### 这一步要告诉 Agent 哪些信息

- 先复现，再修改；
- 说明原因，不要直接重写整个功能；
- 只修改受影响的文件；
- 为这个错误增加测试；
- 修复后运行相关测试和整体回归检查。

### 学生要亲自检查什么

| 测试类别 | 必测内容 |
| --- | --- |
| 数据 | 20 题、每单元 5 题、ID 唯一、每题 4 选项、答案有效 |
| 抽题 | 每轮 12 题、每单元 3 题、无重复、不修改原题库 |
| 作答 | 未答禁下一题、每题只计一次、反馈和解析正确 |
| 流程 | 前后题保留状态、末题结算、重玩完整重置 |
| 结果 | 全对、全错、混合分数、四单元表现、错题数量 |
| 存储 | 最高分只升不降，存储不可用时游戏仍能玩 |
| 界面 | 电脑、手机、200% 缩放、长文字、全错列表 |
| 无障碍 | 键盘、焦点、读屏提示、减少动画、不只靠颜色 |

### 完成标准

- 每个发现的问题都能按步骤复现；
- 修复只影响相关范围；
- 新测试能防止同一错误再次出现；
- 修复后旧功能仍通过回归测试。

## 第 12 阶段：让 Agent 解释项目，而不是替你理解

### 这一步要告诉 Agent 哪些信息

项目完成后，要求 Agent 停止修改，用学生能听懂的语言解释结构。

### 示例提示词

```text
请不要修改任何文件。用小学高年级或初中生能理解的语言解释这个游戏。

请说明：
1. 页面入口在哪里；
2. 20道题保存在哪里，每个字段做什么；
3. 怎样从每单元抽3题；
4. 当前题号、玩家答案、得分和错题怎样保存；
5. 为什么返回上一题不会重复计分；
6. 重新挑战重置什么、保留什么；
7. 自动测试在检查哪些规则；
8. 如果我要安全地改一道题，最少要改哪里、检查什么。

请引用实际文件位置，不要只讲通用概念。
```

### 学生要亲自检查什么

合上 Agent 的回答，试着向同学解释：题库在哪里、抽题怎样保证均衡、答案为什么被锁定、错题怎样产生、最高分为何能跨刷新保留。

### 完成标准

- 你能指出主要文件和它们的职责；
- 你能不用逐行背代码，也说清游戏数据怎样流动；
- 你知道修改题目后必须重新核验答案、解析和来源。

## 第 13 阶段：自己提出一次小升级

先选择一项，不要一次全部加入：

| 升级 | 需要额外想清楚的问题 |
| --- | --- |
| 难度选择 | 难度怎样标注，两个模式是否都覆盖四单元 |
| 收藏错题 | 保存多久，是否只在本机，怎样清除 |
| 单元练习 | 单元内题量不足时怎样处理 |
| 主题切换 | 颜色对比和键盘焦点是否仍清楚 |
| 成就徽章 | 是否鼓励学习，而不是制造同学间压力 |

### 示例提示词骨架

```text
我想在现有游戏中增加【功能名称】。

用户目标：【它解决什么问题】
具体规则：【什么时候出现、怎样操作、边界情况】
本轮范围：【允许修改的文件或功能】
保持不变：【题库、计分、随机、无障碍等】
验收场景：【至少3个具体测试】
失败处理：【缺少数据或存储不可用时怎么办】

请先指出规则中的歧义和风险。我确认后再修改。
```

### 学生要亲自检查什么

你是否真的解释了这个功能为什么有学习价值？有没有同步考虑重玩、手机、键盘和错误状态？新增功能是否破坏原来的计分或题库规则？

### 完成标准

- 功能来自你的决定，而不是 Agent 随意添加；
- 规则和边界情况清楚；
- 原有测试继续通过，并增加了新功能测试。

## 第 14 阶段：展示作品与完成反思

展示时不要只打开游戏。请用“目标—过程—证据—反思”介绍：

1. 我为什么选择做这个游戏；
2. 我怎样把项目拆成阶段；
3. 哪一条提示词最有效，为什么；
4. Agent 实际修改了哪些部分；
5. 我发现过什么问题，怎样描述和修复；
6. 我怎样核验 20 道题；
7. 哪些测试证明项目可用；
8. 哪些决定由我自己作出；
9. 作品还有什么限制；
10. 下一次我会怎样改进共创过程。

### 项目评价量规

| 维度 | 达到要求 | 表现优秀 |
| --- | --- | --- |
| 项目拆分 | 能按阶段完成核心功能 | 每阶段都有范围、验收和证据 |
| 提示表达 | 能说明基本需求 | 能说明目标、限制、边界情况和测试 |
| 内容准确 | 题目有答案和解析 | 每题经过课程来源与人工双重核验 |
| 功能可靠 | 能完成一轮游戏 | 全对、全错、回看、重玩等边界均通过 |
| 问题描述 | 能指出哪里不对 | 能写出复现步骤、预期、实际和修改范围 |
| 界面使用 | 电脑上可操作 | 手机、缩放、键盘和读屏检查完整 |
| Agent 协作 | 能让 Agent 修改项目 | 能审查改动、要求局部修复并解释证据 |
| 责任意识 | 不输入隐私和密钥 | 清楚说明 AI 参与、资料来源和人的责任 |

## 使用 Agent 时必须遵守的安全规则

1. 只在专门的练习项目中操作，先确认工作目录；
2. 不把真实姓名、学校班级、电话、住址和账号放进游戏；
3. 不把 API Key、密码和验证码发给 Agent；
4. 不让 Agent 在来源不明的项目中直接运行高权限命令；
5. 不因为 Agent 说“测试通过”就跳过亲自试玩；
6. 不把 AI 生成的题目自动当成正确答案；
7. 删除、安装、提交、推送和发布要作为单独步骤确认；
8. 发现工作目录、权限或命令不清楚时，先停止并请老师或监护人帮助；
9. 公开展示时说明 Agent 参与了哪些工作；
10. 最终作品由提交者负责检查和解释。

## 真实开发复盘（第一版记录）

这一节来自与本教程同步进行的真实开发，不是根据“常见问题”编出来的故事。记录只写能够用源码、测试输出或运行状态证明的事实；尚未完成的浏览器人工验收也会明确保留。

### 计划与实际有什么不同

原计划是先做一个很小的页面，再逐轮补功能。真实实现仍然遵循“先数据和逻辑、后界面”的顺序，但同一次开发任务中连续完成了三个小阶段：

1. 先建立独立题库和不依赖页面的游戏纯函数；
2. 再接入“开始—逐题—结果”的最小界面；
3. 最后增加均衡随机、上一题复看、分单元表现、错题回顾、最高分、响应式和无障碍。

这样调整的原因是题库结构和状态规则已经足够清楚，可以用自动测试为后续界面提供保护。但这不表示学生也应该一次发送全部要求。课堂练习仍建议每完成一个阶段就试玩一次，因为任务越集中，发现问题后越难定位是哪项改动造成的。

### 每个阶段实际怎样要求 Agent

| 阶段 | 给 Agent 的关键信息 | Agent 的实际交付 | 可以核验的证据 |
| --- | --- | --- | --- |
| 内容审计 | 阅读指定四单元，只列知识点与来源；检查唯一答案；先不写代码 | 从正式发布课程提取 20 个知识检查点 | 题库四单元各 5 题，每题有解析和站内课程链接 |
| 数据与逻辑 | 独立题库；四单元各 5；每轮各抽 3；一次作答；未答禁前进；随机源可注入 | `question-bank.ts` 和 `game-logic.ts` | 纯函数测试可在没有浏览器时检查抽题、锁定、计分和错题 |
| 最小界面 | Client Component；开始—逐题—结果；纯中文；无登录和外部 API | 游戏组件和项目页面 | 生产构建生成静态游戏路由 |
| 功能升级 | 不改题目答案；增加上一题、单元报告、错题、随机重玩和最高分 | 一轮 12 题、结果页和本地最高百分比 | 状态逻辑测试、类型检查与构建 |
| 可访问性 | 原生语义、键盘、焦点、读屏状态、触控尺寸、手机单列、减少动画 | `button`、`fieldset/legend`、`progress`、焦点和状态提示 | 浏览器确认语义结构和题目切换焦点；完整键盘、读屏与手机试玩仍待完成 |


### 真实问题一：测试环境不能直接解析源码导入

**现象：** 使用当前 Node.js 直接加载 `game-logic.ts` 时，文件内部没有扩展名的 TypeScript 导入无法解析。尝试给导入补上 `.ts` 后，项目的 TypeScript 检查又报告 `TS5097`。

**为什么没有直接修改整个项目配置：** 游戏源码本身符合 Next.js 和项目现有 TypeScript 规则。为了只解决测试入口问题而改动 `tsconfig`、打包配置或全部源码导入，范围太大，也可能影响其他页面。

**局部修复：** 测试文件使用项目已经安装的 TypeScript API，把真实的 `question-bank.ts` 和 `game-logic.ts` 临时转换成 CommonJS，再加载转换结果进行测试。测试结束后自动删除临时目录。正式源码继续使用项目原来的导入写法。

**证据：** 五项 `node:test` 全部通过，随后 TypeScript 检查和生产构建也通过。这说明修复同时满足了“测试能运行”和“网站源码仍符合项目规则”两个目标。

这个问题提供了一条很重要的共创经验：**先判断错误属于产品源码、测试入口还是项目配置，再修改最小范围。** 不要看到一个报错就让 Agent “把所有相关文件都重写”。

### 真实问题二：第一次得到 0 分时最高分没有保存

**现象：** 收尾检查发现，保存最高分的函数把“从未保存过成绩”与“旧最高分是 0”都当成数字 0。代码先判断“新分数小于或等于旧分数就不保存”，于是第一次正好得到 0 分时，也不会创建本地最高分记录。

**预期：** 第一次完成挑战时，无论分数是多少，都应该建立一条最高百分比记录；以后只有更高成绩才能覆盖它。

**实际原因：** “没有旧记录”是一种状态，不应该提前转换成 0。空记录和 0 分在业务上含义不同。

**局部修复：** 只有当旧记录确实存在，并且新成绩没有更高时，函数才跳过写入。旧记录为 `null` 时，即使新成绩为 0，也会保存。

**修复范围与证据：** 修改只落在游戏组件的最高分保存逻辑，没有改题库、抽题和计分函数。定向 ESLint、TypeScript 检查和生产构建均通过。当前五项逻辑测试不直接操作浏览器 `localStorage`，因此“首次 0 分是否写入”仍应补一次浏览器人工检查，或以后增加专门的存储单元测试。这里不能把构建通过说成这个浏览器行为已经被完整验证。

### 浏览器人工验收结果与保留项

实现 Agent 当时没有可用浏览器实例；整合阶段重新连接浏览器后，在本地生产预览中完成了一轮桌面端真实试玩。实际验证结果如下：

- 从说明页进入挑战，未答题时“下一题”保持禁用；
- 分别提交错误和正确答案，四个选项立即锁定，并出现正误文字、解析和课程来源；
- 返回上一道已答题后，原选择、正误和总分都保持不变；
- 完成 12 题后得到 3/12、25%，四个单元依次显示 1/3、1/3、1/3、0/3，错题回顾恰好有 9 题；
- “重新随机挑战”把题号、答案和本轮得分清零，同时保留 25% 本地最高分；
- 页面运行期间浏览器控制台没有出现日志或报错；
- 正确反馈、错误反馈、进度、结果报告和错题来源都能从页面语义结构中读取，切换题目后焦点会回到新题标题。

下面这些项目仍不能诚实地写成“已经实际验证”：

- 第一次 0 分时检查最高分是否写入；
- 在手机宽度与 200% 缩放下检查布局；
- 只用键盘完成一轮，并试听读屏状态提示；

这些保留项不是可以省略的步骤，而是本次第一版记录的明确待办。自动测试能够证明抽题和状态规则，生产构建能够证明项目可以编译，桌面试玩证明了本轮实际操作链路；它们仍不能替代手机、完整键盘和读屏环境中的真实用户测试。

### 人与 Agent 的实际分工

- 人确定了面向学生的学习目标、题目范围、必要功能和隐私边界；
- Agent 阅读课程、建立候选题库、实现代码并运行自动检查；
- 课程原文和题库结构为答案核验提供依据，但最终审题仍需要教师或内容负责人逐题确认；
- Agent 的自动检查不能证明题目一定没有歧义，也不能替代手机、键盘、读屏和真实浏览器试玩；
- 是否发布、怎样展示、何时提交和推送，仍由项目负责人决定。

## 项目总结

这个项目真正训练的不是“让 AI 一次写出多少代码”，而是你能不能掌握整个共创过程：

> **人决定目标和边界，Agent 协助执行；程序用测试证明行为，人再用课程与真实操作核验结果。**

当你能把大任务拆小、写清验收标准、看懂改动证据、准确描述问题、要求局部修复，并且知道什么时候应该停下来，你就不再只是一个等待 AI 交答案的人，而是在学习成为项目的设计者、测试者和负责人。
