## 一、最简单的工作方式

1. 每个课程单元在 `docs/markdown` 中建立一个目录。
2. 单元中的每一课新建一个 Markdown 文件。
3. 按照本指南下面的模板填写内容。
4. 图片放在当前课程单元的 `assets` 子目录，并在正文里标明使用位置。
5. 写完后告诉我目录和文件名，以及希望它们按什么顺序发布。
6. 我会负责网站排版、导航、互动效果、图解呈现、运行检查、Git 提交和发布。

推荐使用 UTF-8 编码保存文件。

## 二、文件命名建议

单元目录和课文文件都建议使用“序号 + 简短名称”的形式：

```text
01-认识人工智能/
├── 01-人工智能就在我们身边.md
├── 02-AI系统怎样学习和给出结果.md
├── 03-大语言模型怎样生成回答.md
└── 其他课文.md
```

文件名尽量简短，不要使用下面这些字符：

```text
\ / : * ? " < > |
```

## 三、标题层级

请尽量按照下面的层级编写：

```markdown
# 课程标题

## 本课目标

## 第一部分标题

### 第一部分中的小标题

## 第二部分标题

### 第二部分中的小标题

## 动手试一试

## 检查理解

## 一张图回顾本章

## 本课小结

## 参考资料
```

注意：

- 每个文件只使用一个一级标题 `#`。
- 网站右侧“本页导航”主要根据二级标题 `##` 生成。
- 三级标题 `###` 用于某个部分内部的小主题。
- 不需要手动填写网页地址、锚点或编号，我会在接入网站时处理。

## 五、常用 Markdown 写法

### 普通段落

直接写文字即可。不同段落之间空一行：

```markdown
这是第一段内容。

这是第二段内容。
```

### 加粗和强调

```markdown
这是一个**需要重点理解的概念**。
```

不要连续加粗大段文字，只突出真正重要的关键词或结论。

### 无序列表

```markdown
- 第一项
- 第二项
- 第三项
```

### 有序步骤

```markdown
1. 完成第一步
2. 完成第二步
3. 检查结果
```

### 引用和提示

普通引用：

```markdown
> 这里是一段引用内容。
```

希望在网站中显示为提示卡片时，可以使用：

```markdown
> [!NOTE]
> 这里是补充说明或关键概念。

> [!TIP]
> 这里是学习建议或操作技巧。

> [!WARNING]
> 这里是安全提醒或容易出错的地方。
```

### 先作答，再看参考答案

练习题不要把答案直接放在普通提示框里。希望学生先判断、再自行展开核对时，使用：

```mdx
<AnswerReveal label="我已完成判断，查看参考答案">

- 这里写参考答案。
- 不只给出 A、B、C，还要解释判断理由。

</AnswerReveal>
```

组件内容前后要保留空行，让段落、列表、表格和代码能够按 Markdown 正常解析。同一页有多个练习时，为每个答案写清楚具体名称。

### 链接

```markdown
[链接名称](https://example.com)
```

参考资料尽量提供完整链接，并写清楚资料名称和用途。

### 图片

每个课程单元都在自己的 Markdown 目录中建立 `assets` 子目录。例如：

```text
docs/markdown/01-认识人工智能/
├── 01-人工智能就在我们身边.md
├── 02-AI系统怎样学习和给出结果.md
└── assets/
    └── 01-daily-ai-scenes.png
```

课程 Markdown 与 `assets` 位于同一个单元目录中。网站使用 Next.js 静态导入读取图片，不能只写普通的 Markdown 相对图片路径。先在课文文件顶部导入图片：

```mdx
import courseFigure from "./assets/图片文件名.png";
```

再在需要解释内容的位置使用统一的课程插图组件：

```mdx
<CourseFigure
  src={courseFigure}
  alt="即使看不到图片，也能理解图中关键关系的替代文字"
  caption="这张图在本段中要说明的结论。"
/>
```

`alt` 要说明图中真正重要的关系，不要只写“图片 1”；`caption` 用来告诉读者这张图在当前段落中说明什么。两者不要写成完全相同的一句话。同一章内的图片建议使用序号开头，例如 `01-daily-ai-scenes.png`。流程图和关系图优先使用文字仍可清晰缩放的 SVG；照片或位图插图再使用 PNG、WebP 等格式。

已有的“机器学习与深度学习”和“大模型是如何工作的”章节暂时保留各自的 `assets` 子目录及 `./assets/图片文件名` 引用方式；等章节正式接入网站时，再根据网站资源加载规则统一整理，不影响当前继续编写正文。

如果暂时没有图片，可以先写一个图片需求：

```markdown
> [!IMAGE]
> 希望这里放一张“输入—模型—输出”流程示意图，风格简洁，适合 10—14 岁学生。
```

我接入网站时会和你确认是使用现有图片、制作图表，还是生成新图片。

### 表格

适合比较少量、简短的信息：

```markdown
| 类型 | 主要特点 | 例子 |
| --- | --- | --- |
| 普通程序 | 按明确规则执行 | 计算器 |
| 自动化 | 满足条件后自动行动 | 感应灯 |
| 人工智能 | 根据输入和模型进行推断 | 图片识别 |
```

如果单元格中需要写很长的段落，建议改用小标题或列表。

### 数学公式

短公式写在正文中时，左右各使用一个美元符号：

```markdown
神经网络的输入是 $x$，预测结果是 $\hat{y}$。
```

需要单独居中展示的公式，使用两个美元符号包围，并让公式单独占行：

```markdown
$$
\hat{y}=f(x;\theta)
$$
```

请不要把行内公式写成 `(\hat{y})`，普通圆括号不会触发公式渲染。常用的上标、下标、分数和根号可以分别写成 `$N^2$`、`$x_i$`、`$\frac{a}{b}$` 和 `$\sqrt{x}$`。

## 六、互动内容怎样写

你不需要实现网页互动，只需要描述清楚内容和规则。

### 分类练习

```markdown
## 分类练习：它属于哪一类？

分类选项：人工智能、自动化、普通程序

### 场景 1

- 场景：语音助手听懂提问
- 正确分类：人工智能
- 解释：它需要从语音输入中识别模式，并推断使用者可能表达的意思。

### 场景 2

- 场景：计算器计算乘法
- 正确分类：普通程序
- 解释：它按照明确的数学规则计算。
```

### 单选题

```markdown
### 第 1 题

**题目：** 下面哪一项更符合机器学习的特点？

**题型：** 单选题

**选项：**

- A. 只按照一条固定规则执行
- B. 从示例数据中寻找模式
- C. 每一次都随机选择答案

**正确答案：** B

**答案解析：** 机器学习模型会利用示例数据寻找可以用于新输入的模式。
```

### 开放题

```markdown
### 思考题

**题目：** 找出生活中一个可能使用机器学习的功能，并说明你的判断理由。

**参考方向：** 可以从输入、输出、是否需要识别模式等方面思考。
```

## 七、图解内容怎样写

图不是装饰，而是正文的一部分。遇到下面这些内容时，优先考虑使用图片：

- 多个生活场景放在一起观察时，使用场景图；
- 两个或三个概念需要比较时，使用对比图；
- 一个过程包含多个连续步骤时，使用流程图；
- 一章结束需要串联知识点时，使用知识地图。

每张图只承担一个明确的解释任务，并同时写清楚内容、用途、风格和替代文字。不要在图中堆放大段正文，也不要只依靠颜色表达区别。

## 八、写作建议

- 先写清楚，再考虑写得生动；不用担心网页排版。
- 每一段尽量只表达一个主要意思。
- 第一次出现专业词语时，用生活化语言解释。
- 多使用具体案例，少堆叠抽象定义。
- 面向学生写作时，尽量直接使用“你”与学习者交流。
- 练习题除了写答案，也要写答案解析。
- 抽象概念、流程和对比关系尽量配合图解说明。
- 每张图都要有明确用途和替代文字，不使用纯装饰图片。
- 涉及事实、数据、定义和安全建议时，尽量记录来源。
- 不确定内容是否适合做成互动时，直接标注“请你判断”，我会设计实现方式。

## 九、不需要你处理的内容

下面这些工作由我负责：

- 网站页面地址和技术文件命名
- 左侧课程导航和右侧本页目录
- 上一课、下一课链接
- 字体、颜色、间距和响应式排版
- 提示卡片、测试题、场景图、对比图、流程图和知识地图等网页内容
- 图片尺寸和网页资源路径
- 内容接入、运行检查和浏览器测试
- Git 提交、分支合并和推送

如果你的 Markdown 没有完全按照模板编写也没关系。只要标题、正文、题目、答案、图片需求和资料来源能够区分清楚，我就可以协助整理。
