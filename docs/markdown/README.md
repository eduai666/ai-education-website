## 当前工作重点

当前优先完善 `docs/markdown/01-认识人工智能.md`。已有其他章节不在本轮调整范围；先把第一章的知识讲解、生活案例、图解需求和参考资料补充完整，再根据最终内容设计网页版布局。

第一章采用以阅读和图解为主的形式，不设计答题、评分、分类按钮等网页互动。需要对比、解释流程或回顾知识时，优先使用信息图、流程图和场景图；文字中的观察提示直接服务于理解，不要求学习者提交答案。

叙述面向小学高年级、初中和高中学生。语气要自然、口语化，像老师面对面把一件事讲清楚：先说结论，再举例；句子尽量短；能用日常语言说明的内容，不先堆英文缩写和工程术语。口语化不等于故意装幼稚，准确、简单和一针见血比“教材腔”更重要。

第一章开头先放一张全章框架图，让学习者一眼看到“人工智能—大语言模型—上下文与工具—Agent—人的核验与责任”这条主线。目前 10 张配图已经生成并接入正文；后续调整文字结构时，也要同步检查图片承担的解释任务和正文引用。

第一章要采用清晰的模块化结构：每个二级标题 `##` 表示一个完整的大模块，大模块下面再使用多个三级标题 `###` 拆分概念、案例和问题。每个小标题集中讲清楚一件事，模块之间保持自然的学习顺序，避免把整章写成一段很长的连续正文。

可以参考 [“LLM 和 Agent 的核心术语和原理”](https://labuladong.online/zh/ai-coding/basics/llm-and-agent/) 的标题层级和分块方式，但只借鉴组织形式，不复制其中的文字、示例和讲解顺序。

也可以参考 [Hugging Face Agents Course 的 Unit 1](https://huggingface.co/learn/agents-course/en/unit1/introduction) 对 LLM、消息、工具和 Agent 循环的组织方式。该课程面向成人开发者，第一章只吸收其中清楚的概念路线，不照搬代码、框架教程、思维链示例或不适合未成年学习者的技术深度。

例如：

```markdown
## 人工智能怎样完成任务

### 第一步：接收输入

### 第二步：利用模型进行推断

### 第三步：产生输出

### 第四步：由人核验结果
```

## 一、最简单的工作方式

1. 每一章新建一个 Markdown 文件。
2. 按照本指南下面的模板填写内容。
3. 图片放在 `docs/figures` 中对应章节的子目录，并在正文里标明使用位置。
4. 写完后告诉我文件名，以及希望我将它发布为哪一章。
5. 我会负责网站排版、导航、互动效果、图解呈现、运行检查、Git 提交和发布。

推荐使用 UTF-8 编码保存文件。

## 二、文件命名建议

建议使用“章节序号 + 简短名称”的形式：

```text
01-认识人工智能.md
02-机器学习与深度学习.md
03-大语言模型如何工作.md
04-什么是智能体.md
05-安全使用人工智能.md
```

文件名尽量简短，不要使用下面这些字符：

```text
\ / : * ? " < > |
```

## 三、标题层级

请尽量按照下面的层级编写：

```markdown
# 课程标题

## 本课目标

## 第一部分标题

### 第一部分中的小标题

## 第二部分标题

### 第二部分中的小标题

## 动手试一试

## 检查理解

## 一张图回顾本章

## 本课小结

## 参考资料
```

注意：

- 每个文件只使用一个一级标题 `#`。
- 网站右侧“本页导航”主要根据二级标题 `##` 生成。
- 三级标题 `###` 用于某个部分内部的小主题。
- 不需要手动填写网页地址、锚点或编号，我会在接入网站时处理。

## 五、常用 Markdown 写法

### 普通段落

直接写文字即可。不同段落之间空一行：

```markdown
这是第一段内容。

这是第二段内容。
```

### 加粗和强调

```markdown
这是一个**需要重点理解的概念**。
```

不要连续加粗大段文字，只突出真正重要的关键词或结论。

### 无序列表

```markdown
- 第一项
- 第二项
- 第三项
```

### 有序步骤

```markdown
1. 完成第一步
2. 完成第二步
3. 检查结果
```

### 引用和提示

普通引用：

```markdown
> 这里是一段引用内容。
```

希望在网站中显示为提示卡片时，可以使用：

```markdown
> [!NOTE]
> 这里是补充说明或关键概念。

> [!TIP]
> 这里是学习建议或操作技巧。

> [!WARNING]
> 这里是安全提醒或容易出错的地方。
```

### 链接

```markdown
[链接名称](https://example.com)
```

参考资料尽量提供完整链接，并写清楚资料名称和用途。

### 图片

每一章都要在 `docs/figures` 中建立独立的图片子目录。例如：

```text
docs/figures/01-认识人工智能/
```

由于课程 Markdown 位于 `docs/markdown`，引用图片时使用下面这样的相对路径：

```markdown
![图片中展示的内容](../figures/01-认识人工智能/图片文件名.png)
```

请使用能够说明图片内容的替代文字，不要只写“图片 1”。同一章内的图片建议使用序号开头，例如 `01-daily-ai-scenes.png`。

如果暂时没有图片，可以先写一个图片需求：

```markdown
> [!IMAGE]
> 希望这里放一张“输入—模型—输出”流程示意图，风格简洁，适合 10—14 岁学生。
```

我接入网站时会和你确认是使用现有图片、制作图表，还是生成新图片。

### 表格

适合比较少量、简短的信息：

```markdown
| 类型 | 主要特点 | 例子 |
| --- | --- | --- |
| 普通程序 | 按明确规则执行 | 计算器 |
| 自动化 | 满足条件后自动行动 | 感应灯 |
| 人工智能 | 根据输入和模型进行推断 | 图片识别 |
```

如果单元格中需要写很长的段落，建议改用小标题或列表。

## 六、互动内容怎样写

你不需要实现网页互动，只需要描述清楚内容和规则。

### 分类练习

```markdown
## 分类练习：它属于哪一类？

分类选项：人工智能、自动化、普通程序

### 场景 1

- 场景：语音助手听懂提问
- 正确分类：人工智能
- 解释：它需要从语音输入中识别模式，并推断使用者可能表达的意思。

### 场景 2

- 场景：计算器计算乘法
- 正确分类：普通程序
- 解释：它按照明确的数学规则计算。
```

### 单选题

```markdown
### 第 1 题

**题目：** 下面哪一项更符合机器学习的特点？

**题型：** 单选题

**选项：**

- A. 只按照一条固定规则执行
- B. 从示例数据中寻找模式
- C. 每一次都随机选择答案

**正确答案：** B

**答案解析：** 机器学习模型会利用示例数据寻找可以用于新输入的模式。
```

### 开放题

```markdown
### 思考题

**题目：** 找出生活中一个可能使用机器学习的功能，并说明你的判断理由。

**参考方向：** 可以从输入、输出、是否需要识别模式等方面思考。
```

## 七、图解内容怎样写

图不是装饰，而是正文的一部分。遇到下面这些内容时，优先考虑使用图片：

- 多个生活场景放在一起观察时，使用场景图；
- 两个或三个概念需要比较时，使用对比图；
- 一个过程包含多个连续步骤时，使用流程图；
- 一章结束需要串联知识点时，使用知识地图。

每张图只承担一个明确的解释任务，并同时写清楚内容、用途、风格和替代文字。不要在图中堆放大段正文，也不要只依靠颜色表达区别。

## 八、写作建议

- 先写清楚，再考虑写得生动；不用担心网页排版。
- 每一段尽量只表达一个主要意思。
- 第一次出现专业词语时，用生活化语言解释。
- 多使用具体案例，少堆叠抽象定义。
- 面向学生写作时，尽量直接使用“你”与学习者交流。
- 练习题除了写答案，也要写答案解析。
- 抽象概念、流程和对比关系尽量配合图解说明。
- 每张图都要有明确用途和替代文字，不使用纯装饰图片。
- 涉及事实、数据、定义和安全建议时，尽量记录来源。
- 不确定内容是否适合做成互动时，直接标注“请你判断”，我会设计实现方式。

- 内容接入、运行检查和浏览器测试
