# 怎样选择 AI 编程工具

刚开始接触 AI 编程，最容易被一长串产品名绕晕：这个能补代码，那个能改项目，还有的能自己跑测试。到底该用哪个？

先别急着比品牌。你真正要判断的是：**这次想让 AI 帮到哪一步？**

只解释一段报错，聊天工具就够了；想顺手补全几行代码，用编辑器里的补全工具；要让 AI 搜索整个项目、修改多个文件并验证结果，才轮到编程 Agent 上场。

工具没有绝对的“最强”。任务越大，它要拿到的上下文和权限就越多，你要检查的东西也越多。

## 先看它要替你做多少事

**只问一个问题。** 比如“这段报错是什么意思”。你把必要的代码片段发进对话，普通聊天助手就能解释。它不会自动知道整个项目发生了什么，也没必要获得文件权限。

**补全眼前的代码。** 补全工具跟着编辑器里的光标工作。你写到一半，它根据当前文件和附近代码猜下一段。它很适合重复写法和简单函数，但“补得像”不等于理解了整个项目。

**完成一个项目任务。** 如果要求变成“找出登录失败的原因，修改相关文件并运行测试”，工具就得搜索代码、读取文件、调用终端，再根据结果继续行动。这正是前面学过的 Agent：模型判断下一步，工具执行动作，人检查边界和结果。

## 常见工具其实就这几类

| 类型           | 它通常待在哪里 | 最适合做什么                   | 你要盯住什么                     |
| -------------- | -------------- | ------------------------------ | -------------------------------- |
| 聊天问答工具   | 对话窗口       | 解释概念、讨论方案、生成短示例 | 上下文够不够，答案对不对         |
| 代码补全工具   | 编辑器光标旁   | 补几行代码、完成重复写法       | 补全是否符合当前函数和项目规范   |
| IDE Agent      | 代码编辑器内部 | 跨文件搜索、修改和调试         | 文件差异、命令输出和测试结果     |
| 桌面编程 Agent | 独立桌面工作区 | 管理项目、并行任务、预览和审查 | 工作目录、权限模式和实际执行记录 |

你还会看到终端型 Agent，也就是常说的 CLI。它同样能完成整个项目任务，更适合远程服务器、批量处理和自动化。下一课会专门比较 CLI 和桌面客户端，但不会展开 CLI 安装。

> [!NOTE]
> “桌面版”只是操作界面变成了窗口和按钮，不代表背后没有命令。Agent 仍可能在获得许可后运行构建、测试或 Git 操作。

## 客户端、模型和 API 不是一回事

接入 DeepSeek 或中转站时，很多问题都来自名字混用。把下面三层分开就好：

- **客户端**是你直接操作的软件，例如 Claude Desktop 的 `Code` 标签页，或 ChatGPT Windows 应用中的 `Codex`；
- **模型**负责理解上下文并生成回答或工具请求，例如 Claude、OpenAI 或 DeepSeek 的模型；
- **API 服务**负责接收请求、检查 Key、路由模型和计算费用，模型官方接口、中转站和组织网关都属于这一层。

举个具体例子：Claude Desktop 是客户端，`deepseek-v4-pro` 是模型，`https://api.deepseek.com/anthropic` 是 API 基地址。三者各管一件事。

```text
你提出任务
    ↓
客户端：组织项目、权限和工具
    ↓
API 服务：鉴权、路由、计费
    ↓
模型：生成回答或下一步动作
```

所以，只改模型名称并不能把一个不兼容的接口“变兼容”。地址、鉴权、请求格式、流式事件和工具调用，只要有一处对不上，桌面 Agent 就可能卡住。

## Codex 和 Claude Code 选哪个

截至 2026 年 7 月，二者在 Windows 上都有图形化项目入口：

- Codex 位于 ChatGPT Windows 桌面应用中；很多人仍习惯称它为“Codex 桌面版”。
- Claude Code 的桌面入口位于 Claude Desktop 的 `Code` 标签页。

我的建议很简单：**先看你准备接哪种 API，再看哪个界面用得顺手。**

如果要接第三方服务，重点问服务商这些问题：

| 问题               | 真正要确认的内容                         |
| ------------------ | ---------------------------------------- |
| 能不能打开本地项目 | Windows 版本、项目位置和客户端支持情况   |
| 能不能接入这个 API | 协议、路径、鉴权和模型 ID 是否匹配       |
| 能不能修改文件     | 当前工作目录和权限模式                   |
| 能不能发现错误     | 是否能运行相关检查，你是否会审查结果     |
| 大概要花多少钱     | 模型价格、上下文长度、重试和工具调用次数 |

不要只盯着模型排行榜。模型再强，中转站如果不支持客户端需要的 Responses API、Anthropic Messages、流式事件或工具调用，也很难稳定完成 Agent 任务。

## 为什么后面先讲桌面版

因为更容易看清 Agent 在做什么。

项目、对话、权限提示、文件差异和运行结果通常集中在一个窗口里。初学者比较容易分辨：哪些只是 Agent 说要做，哪些已经真的执行，哪些文件确实被改过。

桌面端也方便把范围缩小到一个练习文件夹。学习阶段先练好“提出任务—观察过程—核验结果”，不用同时处理 Shell、路径和一堆命令参数。

这不是说 CLI 更难就不值得学。等任务变成 SSH、脚本或批量自动化时，CLI 往往更合适。下一课会用同一个只读任务对比两种入口。

## 接入前，先问自己六个问题

1. **任务有多大？** 只解释一段代码，还是要修改多个文件？任务越大，越要说清项目范围、可用工具和停止条件。
2. **协议真的兼容吗？** “OpenAI 兼容”有时只表示支持 Chat Completions，不代表支持 Codex 当前使用的 Responses API；“能聊天”也不代表支持 Claude Code 所需的流式工具调用。
3. **API Key 放在哪里？** 优先使用客户端提供的凭证位置或环境变量，不要把真实 Key 写进项目、截图、聊天记录或公开仓库。
4. **权限开到哪里？** 第一次只打开练习文件夹，从只读开始。编辑、删除、安装、发布和登录账号应该分开确认。
5. **费用怎样计算？** 桌面订阅和 API 计费可能是两套账。长上下文、重试和工具结果都会消耗 Token。
6. **怎样算完成？** “AI 说修好了”不算证据。至少要看文件差异；能运行测试时，还要看真实测试结果。

> [!WARNING]
> 中转站会经过你的提示词、代码和工具结果。接入前先确认运营方、数据处理方式、日志保留、鉴权和费用，不要把学校账号、个人隐私或未公开项目交给来源不明的服务。

## 现在选一次

为下面四个任务选择“聊天问答、代码补全、IDE Agent、桌面编程 Agent”中的一种或几种，并说说理由。

1. 你看不懂一段 12 行的排序代码，只想逐句理解。
2. 你正在写五个结构相似的数据对象，希望快速补全字段。
3. 一个网页项目登录后总是跳回首页，需要搜索多个文件、修改并运行测试。
4. 你收到一个来源不明的压缩包，想让 Agent 用最高权限直接运行里面的程序。

<AnswerReveal label="我选好了，查看参考答案">

1. 聊天问答通常够用，只提供解释所需的代码片段，并核对讲解。
2. 代码补全最直接；完成后仍要检查字段名称和类型。
3. IDE Agent 或桌面编程 Agent 更合适，因为任务需要项目范围的搜索、修改和验证。
4. 不应该直接执行。先确认来源，在隔离环境里进行静态检查并限制为只读；风险没有弄清前就停下来。

</AnswerReveal>

## 记住这条选择顺序

**先看任务，再看入口，最后才看品牌。** 需要的上下文越多、权限越大，检查结果就越重要。
