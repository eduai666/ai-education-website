# CLI 和桌面客户端，到底有什么不同

第一次接触 Codex 或 Claude Code，很多人会卡在一个很实际的问题上：我到底该下载桌面版，还是打开终端？

先说我的建议：**如果你刚开始学，先用桌面客户端。** 项目、对话、权限提示和文件改动都摆在一个窗口里，哪里动过比较容易看清。等你需要远程连接、批量处理或自动化时，再用 CLI 会更顺手。

不过，别把它们理解成“简单版”和“专业版”。两者主要差在你怎样把任务交给 Agent，以及怎样观察它的动作。背后的模型可能相同；权限开得太大时，两边也都可能做错事。

这节不教安装，也不要求你背命令。我们只把同一个任务放到两个入口里走一遍，看清它们各自顺手在哪里。

> [!NOTE]
> 本课产品信息核对于 **2026 年 7 月 31 日**。桌面应用和 CLI 更新速度不同，按钮名称和功能可能随后变化。

## 先把三个容易混的名字分开

**CLI** 是 Command-Line Interface，中文通常叫“命令行界面”。你在 Windows Terminal 或 PowerShell 中输入文字命令，结果也主要以文字显示。

**桌面客户端** 是带窗口、按钮、项目列表和差异面板的图形应用。严格来说，CLI 本身也是一种客户端；为了方便比较，这门课说“客户端”时，通常特指桌面图形客户端。

**API** 则是软件之间传递请求的接口。它不是另一个让人操作的窗口。桌面客户端和 CLI 都可能通过 API 请求模型，但你自己写程序调用 API，是第三种用法。

所以，下面三句话说的不是一回事：

- “我在桌面端打开了项目”说的是操作入口；
- “我使用 DeepSeek 模型”说的是处理请求的模型；
- “请求经过某个中转站”说的是 API 服务和网络路线。

把这三层分开，后面配置地址和排查错误会轻松很多。

## 同一个任务，两种入口怎样完成

假设我们只想了解一个练习项目，不允许 Agent 修改任何东西。任务是：

> 只读取当前项目，不要修改文件，也不要安装软件。列出顶层文件，判断这个项目可能使用什么技术，并说明依据。找不到依据时就说不知道。

### 用 CLI

你会先打开 Windows Terminal，进入练习项目所在的目录，再启动 Codex CLI 或 Claude Code CLI，把任务发给它。Agent 的计划、命令输出和回答主要在终端里出现。

这里最容易犯的错不是命令写错，而是 **进错目录**。CLI 通常把当前目录当作项目范围。发送任务前，先看清终端提示符里的路径；任务结束后，再用版本控制或文件检查工具确认有没有改动。

### 用桌面客户端

你会在 ChatGPT Windows 应用的 Codex 界面，或 Claude Desktop 的 `Code` 标签页中选择练习文件夹，然后在聊天框里发送同一段任务。执行过程、权限提示、文件列表和差异通常会分区显示。

桌面端省掉了“进入目录”这一步，却没有省掉范围检查。窗口里选错文件夹，Agent 一样会读错项目。发送前要看项目名称，结束后要看差异面板是否为空。

同一个任务，两边都能做。真正不同的是入口和工作方式，不是谁“更像真正的 AI”。

## 真正的差别在这里

| 比较项 | 桌面客户端 | CLI |
| --- | --- | --- |
| 怎样打开项目 | 在窗口中选择文件夹或项目 | 在终端中进入项目目录 |
| 怎样提任务 | 聊天框、按钮和快捷操作 | 命令行中的交互提示 |
| 怎样看过程 | 计划、权限、预览和差异面板更集中 | 命令、日志和文本输出更直接 |
| 怎样审查改动 | 适合逐文件查看可视化差异 | 常配合 Git 和其他终端工具审查 |
| 多个任务 | 多个会话或面板比较直观 | 可开多个终端，也方便交给脚本调度 |
| 远程与自动化 | 更适合人在窗口前交互 | 更适合 SSH、批处理、脚本和持续集成 |
| 上手成本 | 对 Windows 新手更友好 | 需要理解目录、Shell、环境变量和命令 |

如果你只是偶尔打开一个项目、和 Agent 一起改代码，桌面端通常更省心。如果你每天都在终端里工作，或者要把任务放进脚本中重复执行，CLI 会更干脆。

## 同一个产品，不代表所有地方完全一样

Codex 的 CLI、IDE 扩展和 ChatGPT 桌面应用共用同一套配置层，通常都会读取 `config.toml`。所以，第 11 课修改用户级 Codex 配置后，桌面端也会受到影响。

但“共用配置”不等于“功能永远同步”。桌面应用和 CLI 可能包含不同版本的 Codex，新功能有时会先出现在其中一边。在 Windows 上还有一个常见例外：原生 Codex 使用 `%USERPROFILE%\.codex`，WSL 里的 CLI 默认使用 Linux 的 `~/.codex`，两边不会自动共用配置和登录状态。

Claude Desktop 的 `Code` 标签页和 Claude Code CLI 使用相同的底层 Agent，项目中的 `CLAUDE.md`、MCP、Hooks 和 Skills 等配置也有很多共通之处。

不过，**第三方推理地址不能照搬。** Claude Code CLI 可以通过环境变量或设置文件连接网关；Claude Desktop 必须在 `Third-Party Inference` 表单中配置。你把 `ANTHROPIC_BASE_URL` 写进终端环境，不代表桌面端会读取它。后面的 Claude Desktop 教程会按桌面入口操作。

## 桌面端不等于更安全，CLI 也不等于更强

桌面端把权限提示做得更直观，但它背后仍可能运行 PowerShell、读取文件和修改代码。CLI 看起来全是文字，也不代表它天然拥有更多模型能力。

无论用哪一种入口，都要检查四件事：

1. 当前打开的是不是专用练习目录；
2. Agent 现在是只读、可写，还是拥有更大权限；
3. 它实际运行了什么、改了哪些文件；
4. API Key、项目内容和费用会交给谁处理。

图形界面能让检查更方便，但不能替你完成检查。

## 一分钟决定用哪个

你可以按下面这条规则选：

- 第一次学习、主要在 Windows 本机操作、想清楚查看文件差异：先用桌面客户端；
- 已经熟悉终端、只能通过 SSH 登录服务器：用 CLI；
- 要重复检查许多项目、接入脚本或持续集成：用 CLI 或专门的自动化接口；
- 要在自己编写的软件里请求模型：直接学习 API，不要把 CLI 当成 API；
- 两边都会用：按任务选择入口，项目文件继续用 Git 或备份保护。

本课程接下来以桌面端为主。这样可以先把注意力放在任务、权限和结果上，不必同时解决一堆终端环境问题。

## 你会怎样选

为下面五种情况选择“桌面客户端、CLI、API”中的一种，并说明理由。

1. Windows 新手第一次打开练习项目，只想阅读 `README`。
2. 电脑不在身边，只能通过 SSH 登录一台没有图形界面的云服务器。
3. 想逐个查看 Agent 修改过的文件和差异。
4. 每天晚上自动检查十个仓库，并把结果交给后续脚本。
5. 正在编写一个网页，希望网页把用户问题直接发给模型服务。

<AnswerReveal label="我已经选好了，查看参考答案">

1. 先用桌面客户端，项目入口和审查区域更直观。
2. 用 CLI，因为远程终端就是现成入口。
3. 桌面客户端更省力；熟悉 Git 的人也可以用 CLI 完成同样检查。
4. 用 CLI 或自动化接口，方便脚本化和批量执行。
5. 用 API。这是在程序中调用模型，不是选择 CLI 还是桌面窗口。

</AnswerReveal>

## 怎么选，记住这一句就够了

**想看得清楚，先用桌面端；想跑得远、跑得多、反复自动跑，再用 CLI。** 两边都只是 Agent 的入口，工作目录、权限和结果始终要由人检查。
