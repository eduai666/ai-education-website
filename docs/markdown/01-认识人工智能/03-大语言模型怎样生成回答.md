# 大语言模型怎样生成回答

**常见的生成式聊天模型，通常不是先找到或想好一整段回答，而是根据当前上下文，一个 Token 接一个 Token 地生成。**

“大语言模型”是一个很大的家族。本课只拆解我们常用来对话和写作的 **自回归生成式大语言模型**，也就是今天常见聊天模型背后的主要类型。

## 核心原理先压成一句话

**这类生成式模型根据当前上下文，预测下一个 Token。**

模型先为下一个 Token 的许多候选项计算分数。生成程序再按设定的策略选出一个，把它加到已有内容后面，继续下一轮。循环很多次后，这些 Token 才组成一句话、一段回答，甚至一篇文章。

这是最核心的生成机制，不是对模型全部能力的完整解释。现实中还涉及训练数据、网络结构、参数规模、指令训练和生成策略。先抓住这条生成主线，再往上叠加其他概念。

## Token：模型处理内容的小单位

### Token 不一定等于一个字

我们看到的是句子，模型处理的则是一串 Token。

Token 可能是一个汉字、一个词的一部分、一个标点，也可能是空格和符号的组合。不同模型使用的切分方法不同，所以不要死记“一个 Token 就是一个字”或“一个英文单词就是一个 Token”。

例如，一个模型可能把英文 `interesting` 拆成类似 `interest` 和 `ing` 的部分；另一个模型可能使用不同切法。具体怎样拆，要以那个模型自己的 Tokenizer 为准。

先记住：**程序先把输入切分并编码成一串可以计算的小单位，模型再处理它们。**

### 输入和输出都会占用 Token

你提出的问题、系统给模型的说明、保留下来的聊天记录、工具返回的资料，以及模型新生成的回答，通常都会以 Token 的形式进入处理过程。

这也是为什么对话越长，模型需要处理的内容通常越多。

## 模型不是只看紧挨着的一个字

预测下一个 Token 时，模型会参考当前上下文中的许多 Token，不只是最后一个字。

现代大语言模型常使用 Transformer 结构，其中的“注意力”机制会计算不同 Token 之间的关系，让和当前预测更相关的内容发挥更大作用。

这里不需要展开公式。先记住：**上下文中的词并不是同样重要，模型会利用它学到的关系寻找更有关的信息。**

## 预测下一个 Token

### 每一轮都有多个候选

假设已有内容是：

> 雨停以后，天空出现了一道……

模型会根据训练中学到的语言模式和当前上下文，为许多候选 Token 计算分数。“彩虹”“亮光”“云霞”等候选的分数可能不同。

问题来了：到底是谁选中“彩虹”？模型提供候选分数，生成程序按当前策略作出选择。如果这一轮选了“彩虹”，已有内容就变成：

> 雨停以后，天空出现了一道彩虹

模型再根据这段新内容，继续预测下一个 Token。

### 完整回答就是循环很多次

把过程压缩一下，就是：

**读取当前上下文 → 模型计算候选分数 → 生成程序选择一个 Token → 加入上下文 → 继续预测**

循环会在模型生成结束标记、达到长度限制，或者外围程序触发停止条件时结束。

对最基本的生成过程来说，模型不是先在某个资料库里找到一段固定答案，再把整段原样取出来。它是在当前上下文中一步步生成新的 Token。

聊天界面常把回答逐步显示出来，这叫流式输出。但屏幕上一次出现一个汉字，不代表那个汉字就一定等于一个 Token；应用可以缓存、合并或拆开显示内容。生成机制要看模型和接口说明，不能只凭打字机动画判断。

## 只会预测，为什么还能完成复杂任务

### 模型从大量文本中学到了许多模式

训练材料中包含语言结构、知识表达、问题与回答、代码和不同类型的写作。模型在练习预测 Token 的过程中，会学到非常复杂的关系。

因此，“预测下一个 Token”听上去简单，却可以组合出翻译、摘要、问答和代码生成等能力。规模和训练方式很重要，不能把今天的模型理解成只看前一个字的简单接龙程序。

### 从“继续写”到“回应指令”

只经过基础预训练的语言模型，更像一个续写器。你输入“中国的首都是”，它可能直接接着写“北京位于……”。

我们平时使用的聊天模型通常还经过指令训练，让它更擅长把输入理解成提问、要求或任务。例如，你说“请用三句话解释光合作用”，它会尝试按要求回答，而不只是接着你的句子往下写。

这类模型常被叫作 **Instruct Model（指令模型）**。它的底层仍然在生成 Token，只是训练让它更会遵循不同类型的指令。

### 能力强，不等于工作方式和人一样

模型能完成复杂任务，不代表它拥有人的生活经历、情感或意识。它处理 Token 和模式的方式，与人通过身体、经验和社会生活理解世界的方式并不相同。

## 为什么同一个问题，回答会变化

### 模型不一定永远选同一个候选

生成程序可以总选分数最高的候选，也可以在几个较合适的候选中抽样。后者会让表达更多样，但回答也更容易发生变化。

有些系统提供一个叫 **Temperature（温度）** 的设置，用来影响候选选择有多集中。通常温度较低时输出更稳定，温度较高时表达更多样。它不是“聪明程度”或“事实可信度”按钮；温度低的回答仍然可能错，温度高也不等于更有创造力或更好。

换了模型、问题写法、聊天记录或工具结果，候选 Token 的可能性也会跟着变化。

所以，同一个问题出现不同回答很正常。变化本身不代表模型突然变聪明了，也不代表它一定变差了。

## 说得顺，不等于说得对

预测“接下来什么内容更可能出现”，和核实“现实中什么为真”，不是同一件事。

模型可能把不完整的信息接成一段听起来很合理的回答，也可能混淆人物、日期和来源。这类流畅却不可靠的内容，常被人称为“幻觉”。

“幻觉”不是模型真的看见了不存在的东西，而是一个方便的说法，表示它生成了缺少事实依据或与事实冲突的内容。

语句通顺只能说明表达连贯，不能代替事实核验。当任务需要最新资料、精确数字或可追溯来源时，还要查询可靠资料，而不能只信一次生成。

## 本课小结

- 本课讨论的自回归生成式大语言模型，最核心的生成机制是根据上下文预测下一个 Token。
- Token 是模型处理内容的小单位，不固定等于一个字或一个单词。
- 模型会参考上下文中许多 Token 之间的关系，不是只看最后一个字。
- 一个 Token 加入上下文后，模型会继续预测，许多轮共同组成完整回答。
- 指令训练让聊天模型更擅长回应任务，但底层仍然在逐步生成 Token。
- 回答自然流畅，不代表其中的事实一定正确。
