# 项目开发环境要求

> 适用项目：AI 基础教育公益网站
> 更新日期：2026-07-26
> 目标：保证两位成员使用一致、可复现的本地开发环境。

## 1. 环境基线

| 项目 | 团队基线 | 说明 |
| --- | --- | --- |
| Node.js | `24.13.0` | 建议通过 NVM 安装，两人保持一致 |
| npm | `11.6.2` | 项目只使用 npm，不混用 pnpm、Yarn 或 Bun |
| Git | `2.43.0` 或更高 | 用于分支、PR 和版本管理 |
| 框架 | Next.js `16.2.12` | 版本以 `package.json` 和 `package-lock.json` 为准 |
| 系统 | Ubuntu 24.04 已验证 | macOS 或 Windows 11 + WSL2 可用，但 Node/npm 版本必须一致 |

Next.js 当前要求 Node.js `>=20.9.0`，但本项目不以最低版本作为协作基线。成员 A 已在 Ubuntu 24.04.4、Node.js 24.13.0 和 npm 11.6.2 上完成 `lint` 与生产构建验证。

## 2. 硬件与网络

- 建议至少 2 核 CPU、8 GB 内存和 2 GB 可用磁盘空间。
- 本地开发不需要独立 GPU、CUDA、Conda、Docker 或云服务器。
- 首次安装依赖需要访问 npm Registry。
- 开发服务默认只供本机访问，不应无意绑定到 `0.0.0.0`。

## 3. 首次安装

```bash
git clone https://github.com/eduai666/ai-education-website.git
cd ai-education-website

nvm install 24.13.0
nvm use 24.13.0

npm ci
```

禁止使用 `sudo npm install`。所有依赖必须安装在项目内的 `node_modules/`，不修改全局 npm 环境。

## 4. 日常命令

```bash
# 仅监听本机
npm run dev -- --hostname 127.0.0.1

# 代码检查
npm run lint

# 生产构建，同时执行 TypeScript 检查
npm run build
```

本地访问地址：`http://127.0.0.1:3000`。

提交 PR 前至少完成：

```bash
npm run lint
npm run build
git status
```

## 5. 依赖管理规则

- `package-lock.json` 必须提交，且只能由 npm 更新。
- 普通安装使用 `npm ci`；只有明确增删依赖时才使用 `npm install`。
- 修改依赖的 PR 必须说明原因，并单独审核 `package.json` 和锁文件差异。
- 两人不要同时修改锁文件。
- 不运行来源不明的 npm 包、安装脚本或未审核 PR。

## 6. 环境变量与密钥

V0.1 静态原型不需要模型 API 密钥。未来增加服务端能力时：

- 本地秘密只写入 `.env.local`；
- `.env.local` 必须被 Git 忽略；
- `.env.example` 只保留变量名和非敏感示例；
- 任何密钥都不得使用 `NEXT_PUBLIC_` 前缀；
- 不在代码、Markdown、截图、日志或 Git 历史中保存密钥。

## 7. 当前安全告警基线

截至 2026-07-26，`npm audit --omit=dev` 报告 3 个 high 级别的受影响包记录，来自 Next.js 的间接依赖：

- `postcss@8.4.31`：只有在构建不可信 CSS 或 source map 时才与当前项目相关；
- `sharp@0.34.5`：只有处理不可信图片时才与当前项目相关。

当前项目不接收用户 CSS、不开放图片上传，也没有配置任意远程图片源，因此现阶段可继续开发。

处理规则：

- 不执行 `npm audit fix --force`，它会将 Next.js 错误降级并引入依赖冲突；
- 定期执行 `npm audit --omit=dev`；
- 优先升级到完成修复的 Next.js 稳定版；
- 公开上线前必须重新评估并处理这些告警。

## 8. 隔离边界

- 当前开发不要求 Docker；项目级 `node_modules` 和普通用户权限足以满足日常协作。
- 不可信 PR 应交给 GitHub Actions 或不挂载用户主目录与密钥的受限容器检查。
- 学生作品首版只允许自包含的 HTML/CSS/JavaScript，并在独立来源的 sandboxed iframe 中运行。
- 首版不执行任意服务端代码、npm 项目或用户上传脚本。

## 9. 环境问题排查

开始排查前先记录：

```bash
node --version
npm --version
git --version
npm run lint
npm run build
```

如果问题只在一位成员的电脑出现，先对比 Node.js、npm、锁文件和环境变量，不要立即删除锁文件或强制升级全部依赖。
