# 第一章图片生成提示词

本章 10 张图片已经使用 `gpt-image-2` 生成，格式均为 **PNG 位图**，没有使用 SVG。最终文件位于当前目录。

- `01-daily-ai-scenes.png`：初次接口测试，medium 质量，请求尺寸 `1536 × 1024`。
- `02`—`10`：最终批次，high 质量，请求尺寸 `2048 × 1152`。
- 兼容端点最终返回：第 1 张为 `1693 × 929`，其余为 `1672 × 941`，均为 RGB PNG。
- `04`、`05`、`07`、`10` 在视觉复核后做过定向重绘；下面保存的是最终采用版本的提示词。

复现某张图片时，把“统一风格要求”和对应图片的“具体提示词”一起发送。

## 统一风格要求

```text
用途类型：scientific-educational，面向小学高年级、初中和高中学生的中文人工智能基础课程网页插图。

输出要求：横向 16:9，高质量、不透明背景的 PNG 位图，不要 SVG。

视觉风格：原创现代中文教育信息图，简洁扁平 2D 插画，结构清楚，圆角卡片，统一线条，留白充足；友好但不过度幼稚；不使用写实照片、3D 渲染、赛博朋克或复杂电路背景。

颜色：浅灰白背景，以深蓝 #2458C6、青绿 #0B766E、深灰蓝 #263248 为主，少量柔和黄色和橙色强调；色盲安全、高对比。

文字：只出现具体提示词中明确允许的文字，简体中文必须逐字准确，使用清晰的无衬线字体；不自动添加标题、英文、数字、说明段落或装饰文字。

约束：不使用真实品牌、商标、产品界面或水印；不模仿已有网站画面；不把 AI 画成人脑、有意识的机器人或魔法装置；画面边缘保留安全留白。
```

## 01｜生活中的技术场景

文件名：`01-daily-ai-scenes.png`

```text
在横向画布中安排 5 个独立场景卡片：进行简单乘法计算的计算器；夜晚有人经过时自动亮起的感应灯；手机相册把同一个人的不同角度照片整理成一组；无品牌的视频平台根据观看记录排列推荐内容；语音助手接收声音波形并回应。

只允许出现：“计算器”“感应灯”“手机相册”“视频推荐”“语音助手”。

不要标注“人工智能”“自动化”“普通程序”等分类答案。这张图只负责让学习者观察不同技术怎样接收信息和产生结果。
```

## 02｜普通程序、自动化与人工智能

文件名：`02-program-automation-ai.png`

```text
制作三栏等宽对比图。第一栏用计算器和清晰步骤符号表现普通程序；第二栏用光线传感器连接灯泡表现自动化；第三栏用多张不同角度的猫照片进入抽象模型并得到分类表现人工智能。三栏下方用无文字连接带说明真实产品可以组合三种方式。

只允许出现：“普通程序”“明确规则”“自动化”“条件触发”“人工智能”“模式推断”。

不要把三类画成互相排斥的三种设备。
```

## 03｜输入—模型—输出—核验

文件名：`03-input-model-output-check.png`

```text
制作从左到右的四步流程图，以判断照片里是否有猫为唯一例子：清楚的猫照片进入系统；抽象、非拟人化的模型模块提取轮廓、耳朵、纹理等特征；产生带不确定性提示的“可能是猫”结果；一名学生对照原图进行最后核验。箭头清楚，最后的核验步骤视觉上最醒目。

只允许出现：“输入”“模型”“输出”“核验”“可能是猫”。

不要出现概率数字、代码、训练过程或数据库。
```

## 04｜预测下一个 Token

文件名：`04-next-token-prediction.png`

```text
制作单一、顺时针的五步循环，不要复制两套候选列表：

1. “当前上下文”卡，内容为“雨停以后，天空出现了一道……”；
2. “候选 Token”，只列“彩虹”“亮光”“云霞”及无数字的可能性横条；
3. “选择一个 Token”，突出“彩虹”；
4. “加入上下文”，必须显示“雨停以后，天空出现了一道彩虹”，不能保留省略号；
5. “继续预测”，箭头回到循环开头。

只允许出现以上文字。不要绘制第二套候选 Token，不要暗示下一轮还要继续选择“彩虹”，不要出现百分比。
```

## 05｜上下文窗口

文件名：`05-context-window.png`

```text
右侧大型容器顶部显示“上下文窗口”，内部放五张卡：“系统消息”“当前问题”“历史消息”“检索资料”“工具结果”，底部有无数字容量条。

左侧单独放一张较早的“历史消息”卡。由这张卡引出两条完全独立的路径：橙色箭头从左下角指向垃圾桶，箭头旁标“删减”；绿色箭头从右下角指向“摘要”卡，再从摘要卡指回上下文窗口。绿色路径不能经过垃圾桶或“删减”，也不能从历史消息直接回到窗口。

只允许出现：“上下文窗口”“系统消息”“当前问题”“历史消息”“检索资料”“工具结果”“删减”“摘要”。
```

## 06｜一次工具调用

文件名：`06-tool-calling.png`

```text
制作横向闭环流程图，明确区分模型、控制程序和外部工具。流程依次为：使用者提出需要实时信息的任务；模型生成包含工具名称和参数的请求；控制程序检查权限和参数；外部工具实际执行；结果进入上下文；模型根据结果继续回答。模型、控制程序和工具使用不同形状，突出权限检查节点。

只允许出现：“提出任务”“生成工具请求”“检查权限”“执行工具”“返回结果”“继续回答”。

不要暗示模型亲自浏览网页、读取硬盘或执行动作；不要出现 API、JSON、代码或品牌。
```

## 07｜Agent 任务循环

文件名：`07-agent-loop.png`

```text
中心为科学馆图标和“目标”，主循环顺时针只用四个节点：“观察”“判断”“行动”“检查”，然后回到观察。外侧四个模块是“模型”“任务记录”“工具”“人工确认”。

工具模块旁可以画搜索官网、开放时间、交通三个无文字图标。低风险工具路径从“行动”直接到“工具”；另画一条独立橙色高风险支路，从“行动”先经过“人工确认”，再到一个无文字的预约或提交图标。人工确认路径不能连接任务记录或交通查询。

只允许出现：“目标”“观察”“判断”“行动”“检查”“模型”“任务记录”“工具”“人工确认”。
```

## 08｜让 Agent 更可靠

文件名：`08-agent-reliability.png`

```text
制作“行动前约束 + 行动后反馈”的双侧信息图。中间是简化的 Agent 循环；左侧用钥匙与盾牌、参数表单与放大镜、计数器、人工确认按钮表现行动前保护；右侧用资料来源标记、测试清单、日志记录、人工复核表现行动后验证。两侧箭头共同指向更可靠但并非绝对正确的任务结果。

只允许出现：“行动前约束”“最小权限”“参数检查”“次数限制”“人工确认”“行动后反馈”“来源核对”“测试”“日志”“人工复核”。

不要出现“绝对安全”“零错误”、满分或惩罚图标。
```
